# Image Search Skill

来源：`docs/产品设计/simple-skill-pipeline-四类规则归一.md`  
版本：当前确认版本  
定位：按 Image Skill 责任拆分后的运行输入与接口规范；内容业务规则仍追溯到 `rules/01—06`，不构成第二套并列业务规则。

真实调用入口：`app/server/simple-image-skill.mjs` 的 `runImageSearchSkill()`。

## 1. Purpose

根据 Planner 提供的一批图片 slot，搜索、筛选、排序并选择符合事实和视觉要求的真实图片。可以处理封面、酒店、特色餐饮、交通、DAY 和 Planner 已创建的可选增量图片位。

本 Skill 不自行创建、取消或降级必需图片位，不修改事实、文案或模块结构。

## 2. When to use

当 Planner 已经给出图片位的业务事实、视觉职责、比例和锁定状态，需要批量完成真实图片检索与选择时使用。

不要用本 Skill 生成 AI 图片、改写文案、改变行程安排或决定页面骨架。

## 3. Input Contract

一次接受 `slots[]`。每个 slot 至少包括：

- `slotId`
- `moduleType`
- `required`
- `location`（如适用）
- `hotel`（如适用）
- `activity`（如适用）
- `subject`（如适用）
- `visualGoal`
- `visualContext`
- `copyTargetId`
- `aspectRatio`
- `userLocked`
- `adjacentCopy`（可选）

不是所有可选事实字段都必须同时非空，应按 slot 类型使用。`visualContext` 是当前 DAY 或模块的真实图片语境，不是预先生成的客户文案；`copyTargetId` 用于关联对应 Copy Task。如果最终文案已经存在，Program 可以补充 `adjacentCopy`；如果不存在，本 Skill 必须仅根据结构化事实、`visualGoal` 和 `visualContext` 完成首轮搜索。

`mustHave`、`prefer`、`forbid` **不是 Planner 输入字段**，不得要求 Planner 提供。

## 4. Constraint Building

Image Skill 根据当前 slot 事实、`moduleType`、`visualGoal`、`visualContext` 和正式 Image Skill Rules，在内部生成：

- `mustHave`：当前图片不可妥协的事实条件，例如正确地点、正确酒店身份、正确活动和正确主体。
- `prefer`：只影响候选排序的视觉偏好，例如自然光、高端感、干净度、构图、临场感和客户想象空间。
- `forbid`：明确不可采用的条件，例如错地点、错酒店、错活动、错主体、水印、AI 图、破图和明显低质。

构建约束时：

- 不得创造 Planner 未提供的新行程事实；
- 不得修改事实或扩大活动范围；
- 不得把软视觉偏好升级成事实硬条件；
- 不得用分数替代地点、酒店身份、活动和主体的事实判断。

正式职责为：Planner 决定“我要什么图”；Image Skill 决定“找到这张图时什么必须满足、什么优先、什么不能出现”。

## 5. Search Batch

“一轮自动搜索”是一次完整的 Image Skill 业务执行批次，不是一个 slot 只允许一个 query。

同一批次内，可围绕每个视觉目标：

- 生成有限数量的不同搜索表达；
- 并发搜索多个允许来源；
- 统一合并候选、去重、技术过滤、主体判断、视觉排序并选择推荐图。

一次可处理多个 slot，并在内部按受控并发执行；不得机械实现成一个 slot 一次串行完整 Skill 调用。并发数量是 Program 技术配置，不进入本 Skill 的业务规则。

本批次完成后，不得因结果不理想自动启动第二轮业务搜索，也不得进入 Reviewer → Agent → targeted retry → 再搜索。只有用户主动要求重新搜索某个 slot 时，才创建新的 Image Skill 请求。

## 6. Image Rules

### 6.1 搜索目标

- 封面：强调目的地代表性、整程核心体验和标题承载空间。
- 酒店：强调酒店身份正确、真实空间和住宿品质。
- 特色餐饮：强调真实用餐形态、餐桌或服务场景。
- 交通：强调交通类别正确，不形成未经确认的车型承诺。
- DAY：强调当天地点、核心活动和视觉主体。

### 6.2 来源优先级与官网判断

来源优先级为：用户原始或已授权素材；运营方官网与官方媒体；旅游局或目的地官方媒体；可信酒店联盟或行业组织；授权信息清晰图库；可信媒体或供应商；其他第三方。

- 官网身份主要依据官方域名，页面标题或 URL 出现品牌名不能单独证明官网。
- 来源可信不能替代主体判断；来源可追溯不等于商业授权已确认。
- 网页图片提取优先 `og:image`、`twitter:image`、最大尺寸 `srcset`、懒加载字段、JSON-LD 和有明确语义的正文图片。
- 排除 Logo、图标、头像、二维码、sprite、追踪像素、重复 URL 和无来源页孤立图片。

### 6.3 事实匹配与筛选顺序

筛选顺序为：事实匹配 → 模块职责 → 水印/破图/明显低质 → 品质与构图 → 裁切和整程节奏。

- 事实匹配优先判断地点、酒店身份、活动和主体。
- 相关度、奢游感、干净度和构图分数只能用于排序，不能独立决定硬拒绝。
- 未完成真实主体判断时，不得伪造通过状态或默认分数。

### 6.4 模块图片要求

- 酒店图片必须确认酒店身份，优先酒店本体、客房、公共空间、景观和有依据的设施；不能只凭建筑风格判断身份。
- DAY 与活动图片必须匹配当天地点、活动和主体，不得用相似景点、其他国家、其他酒店或其他活动替代。
- 酒店图只有在 Planner 已确定 DAY 核心视觉职责为酒店、入住或酒店体验时才能用于该 DAY；不得作为活动图未找到后的自动替代。
- 餐饮图片必须匹配原始资料中的餐饮形式和场景，不得凭视觉吸引力虚构菜品、地点或服务。
- 交通图片必须匹配交通类别；车型未保证时可以使用同等级示意，但不能暗示已指定车型。
- 多图必须承担不同视觉职责，不为凑数量使用重复机位或同义画面。
- 连续相似 DAY 的 slot 应结合 Planner 给出的 `visualGoal`、`visualContext` 和相邻重复约束，在真实候选中通过环境、行动、主体、景别、构图和视觉职责形成差异。
- 连续 DAY 必须避免同一张图片、同场景连拍、几乎相同机位和没有明显视觉差异的同义画面。如果 Planner 已说明事实不足以区分，不得为了差异化虚构动物、天气、时间段、活动或场景。

### 6.5 视觉质量、构图与比例

- 图片应真实、干净、高端、有品质，并具备目的地或体验辨识度。
- 避免过度 HDR、强滤镜、荧光色、灰脏、死白、噪点、严重曝光、明显 AI 感、超现实畸变、卫生疑虑和严重负面人物状态。
- 默认使用 `cover`；车辆、房间结构和餐饮细节等证据型图片可使用 `contain`。
- 复合卡最多两图，两图必须证明不同子体验；在 2000px 中不可辨认时拆卡或只保留强项。

### 6.6 去重与采用资格

- 相同文件、近似裁切图、相似机位和跨模块同义画面不得重复使用。
- 同一家酒店的不同主体图片可以使用，但视觉职责必须不同。
- 错地点、错酒店身份、错活动、错主体、明显水印、破图、明显低质、不可下载、不可解码和 AI 生成图片不得选择。

## 7. Output Contract

按 `slotId` 独立返回每个图片位：

- `status`: `success | not_found | needs_user_action | failed`
- `selected`
- `candidates`
- `queriesUsed`
- `sourceEvidence`
- `actualSubject`
- `matchReason`
- `technicalStatus`
- `warnings`

成功结果必须能追溯实际搜索词、候选、实际主体、来源和身份依据、事实匹配、技术可用状态、淘汰原因、排序及最终推荐图。无合格图片时不得伪造成功。

`mustHave`、`prefer`、`forbid` 可作为 Skill 内部约束与结果解释信息保留，但不能反向改写 Planner 事实。

## 8. Failure Semantics

- 一个 slot 失败或未找到，不得影响其他 slot。
- 无合格图片返回 `not_found`；需要用户补充、确认或主动处理时返回 `needs_user_action`；技术执行失败返回 `failed`。
- 必需 slot 未解决可以阻止最终 100%，但不能阻止其他仍可执行的 slot 继续。
- 可选 slot 无合格图片时由后续 Program 按规则移除并重排。
- 不得自动定向重搜；只有用户主动要求重新搜索该 slot 时才发起新请求。

## 9. Forbidden

禁止修改文案、事实或模块；禁止创建、删除或降级必需图片位；禁止 AI 生成图片兜底；禁止自动第二轮搜索、自动定向重搜、`review_decision`、finding package、Reviewer 闭环和 stage budget 业务循环；禁止单个目标失败导致整批或整阶段重跑。

同时禁止无视觉判断默认 pass，以及在 DAY 活动图未找到时自动使用酒店图替代。
