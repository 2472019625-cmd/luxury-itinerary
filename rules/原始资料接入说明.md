# 原始报价单／行程单接入规则

> **历史迁移文件**：当前有效内容已迁入 `02-数据事实与字段映射.md`、`03-品牌文案与模块内容.md` 和 `04-图片搜索与使用规范.md`。本文件仅供迁移核对与历史追溯，不再作为当前执行依据；冲突时以 01—06 正式规则为准。

当前模板支持把定制师提供的原始表格或长图资料整理成结构化行程数据，再直接渲染为最终品牌长图。

## 数据映射

- 日期、路线、行程详情、餐食、酒店、用车、报价和费用包含分别进入对应模板组件。
- 原始表格中的文件名、主标题、副标题和海报下方亮点要分开处理：文件名/原主标题只作参考，客户版封面标题必须重新生成，且包含目的地、天数晚数和定制游属性。
- 原始副标题若只是酒店清单，不直接作为客户版副标题；酒店清单进入住宿板块或产品亮点，封面副标题改写为体现定制游节奏、路线画面和核心体验的一句话。
- 原始表格里的“海报下方亮点 / 主推亮点 / 核心卖点”优先进入产品亮点候选池，保留其短标题并扩写为客户版表达，再与奢游公司优势组合。
- 供应商表中的“简要行程”拆为 `routeNodes`、预计车程和途中休息；每日主题由已确认的路线与体验事实概括生成，不得添加原资料没有的项目。
- 酒店先按正式名称归一，再按连续住宿段合并进入 `hotels`。必须区分已确认、拟入住、参考酒店和同级备选，并记录房型、晚数、选择理由与替换规则。
- 交通按城市接送、游猎车辆、境内航班、船只等场景归类。默认只承诺车辆等级与座位数；只有来源明确确认时才设置 `modelGuaranteed: true`。
- 普通早中晚餐进入结构化 `mealPlan`，不自动配图；草原早餐、落日酒会、丛林晚餐等已确认特色餐饮可进入 `special` 并配置图片。
- `diningExperiences` 对应客户版独立板块，板块名固定为 `特色餐饮`。不要使用 `风味体验` 作为正式客户版标题。
- 房型、餐食计划、基本房型报价、报价测算依据等可以作为内部抽取字段保留，但不得直接渲染到客户版酒店卡片或注意事项中。
- 若客户版需要说明报价有效期、补差或最终确认为准，应放在费用说明中的客户版 `报价说明`，不得放入注意事项，也不得展示内部测算逻辑。
- 推荐、自费、视时间安排、天气依赖和野生动物依赖项目必须进入状态字段，不得改写成已包含或保证体验。
- 供应商表中的成本、汇率、加价倍率和利润属于内部数据，禁止进入客户 JSON 和渲染页面。
- 供应商表中的备注、注意、参考、报价有效期等字段必须先做客户可见性判断：内部操作信息删除；客户需要知道的履约边界改写成温和说明。
- 原资料没有的日期、保险或退改政策不得从旧样例继承，也不得自行编造；定制师名片使用默认头像与“定制师名字 | 资深定制师”占位，后续由应用端让定制师自行上传和配置。
- 原资料存在含义不明或互相矛盾的字段时，暂不写入成品，并记录在数据文件的 `sourceNotes` 中等待确认。

## 图片优先级

1. 优先裁取并使用原始资料中的真实照片。
2. 不足时搜索可核验地点和来源的真实照片，并在 `assets/travel/<dataset>/sources.json` 记录来源。
3. 搜索仍无法得到合适照片时，才生成与当天内容对应的图片。
4. 正式版每天使用2图或4图；导入校验不允许0图、1图或3图。
5. 同一份客户长图内，封面、酒店、特色餐饮、交通和每日行程的旅行图片必须全局唯一，不复用同一文件、同一裁切或同一来源照片。
6. 图片任务清单必须逐卡写明“图片要证明什么”。餐饮要证明具体餐饮形态，交通要证明交通类别，酒店要证明住宿价值，每日行程要证明当天体验。

## 客户文案规则

- 景点卡片回答“最值得体验什么、客人会做什么”，不写纯百科式介绍。
- 不在客户文案中展示“原始资料照片”“经地点核验”等内部图片来源说明。
- 迁徙、渡河、捕猎、雪山能见度和野生海洋生物相遇等自然现象必须明确不可保证。
- 签证、疫苗、黄本、保险和入境政策属于时效信息，出图前必须重新核验；无法核验时写“以出发时官方要求为准”。
- 注意事项采用客户友好提醒，不照搬供应商备注。默认覆盖行程节奏、气候穿着、活动安全、自然现象、证件财物行李、儿童长者与特殊需求。
- 产品亮点必须由奢游可复用品牌/服务价值和本行程独有卖点共同组成；若原始资料已有海报亮点，应优先吸收并扩充，不能只改写每日景点摘要，也不能只写公司优势。
