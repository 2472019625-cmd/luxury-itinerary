# 04 图片搜索与使用规范

版本：1.5
生效日期：2026-09-02
适用范围：图片蓝图、图片位、搜索、下载、审核、采用、去重、编辑器换图、来源与授权、2000px 版面复查。本文是图片领域唯一当前正式规则。

## 已裁定流程口径

- 不设置独立图片人工审核页。
- 后台保留 `auto_approved/manual_review/hard_rejected`，但 `manual_review` 不阻止任务完成或进入编辑器。
- 只有成功完成终审、达到自动采用标准且已保存到本地的图片可自动入稿。
- 最终客户成品不得出现空白图片位；预算耗尽后，非必需图片位从客户版面移除并自动重排，必需视觉缺图进入待用户确认。
- 最低视觉覆盖为：封面至少1张真实可用图片、每个实际展示的酒店模块至少1张主图、每个实际展示的 DAY 至少1张主图。第二张、装饰图和细节图属于可选位，无合格图时移除并重排。必要性由版本化产品配置和程序判定，AI只能建议可选增量。
- 生成100%和进入编辑器不以商业图片授权确认为前提；正式导出必须另行通过授权门禁。
- 用户在编辑器选择、上传、移动或清空图片后必须锁定。

## IMG-003—005 图片故事与模块审美细则

本节把仍有效的影像判断写回当前唯一图片规则。它不机械增加图片数量：目标图数用于规划，合格图片不足时按FLOW-004移除非必需位并重排；必需视觉覆盖不得删除或留空。带示例的条款只帮助判断，不要求逐字或逐图模仿，也不能提供新的行程事实。

### 1. 整体影像顺序

候选判断顺序固定为：先核对地点、品牌、活动和主体事实 → 再判断是否符合模块职责 → 再比较品牌质感和客户想象空间 → 最后检查裁切与整程节奏。漂亮不能抵消事实错误，官方来源也不能抵消主体错配。

最终图片故事应同时追求：高端与私密感、自然真实、快乐松弛、构图与清晰度品质、目的地或体验辨识度。至少有一个可说明的客户价值和一个具体事实主体，不能只依靠“豪华氛围”。

### 2. 色调、光线、人物与场景

- 优先自然采光、日出日落、柔和侧光或克制室内暖光；色彩可浓郁但不过饱和，天空、海水、植被、木石等自然色应稳定耐看。
- 强滤镜、荧光色、过度 HDR、灰脏、死白、明显噪点、闪光灯直打和严重曝光异常至少降低为 `manual_review`；已造成严重低质、失真或主体不可辨时才按证据进入 `hard_rejected`。
- 人物应自然、放松、得体并与场景发生关系；服务人员应着装整洁、动作专业。自拍大头、游客打卡、尴尬裁切、疲惫焦虑、争吵、抽烟酗酒、过度性感化或明显表演感不得自动入稿；无明确硬伤但品牌不适配时保留为 manual 供人工判断。
- 室内重材质、秩序、干净度和服务细节；室外重主体、尺度与目的地辨识度。明显 AI 感、超现实、严重畸变、杂乱拥挤、低档设备或卫生疑虑属于禁止方向。
- 上述主观项由视觉模型排序、生成后整体复查和人工审美共同负责；没有可验证硬错时不得仅凭“高级感不足”把候选记为硬拒绝。

### 3. 模块正反例

- 封面：优先整程最具代表性的目的地大场景、稀缺体验或标志性住宿与环境关系，并保留标题安全区。普通卧室、Logo、拥挤街景、自拍、主体过小或与整程无代表关系的局部图不适合作封面。
- 酒店：优先酒店身份可核验的外观、客房与景观、私人露台、泳池、餐厅、水疗或特色公共空间；图片须证明“为什么值得住”。其他酒店、门头/Logo、普通风景、老旧杂乱空间和低清官方小图不得冒充目标酒店价值。
- 特色餐饮：必须看见对应餐饮形态、餐桌、餐食、服务或真实用餐环境。酒窖/品酒、丛林早餐、星空/Boma/Bush Dinner、主题烤肉等只在本次事实存在时作为搜索类型；普通门头、大堂、树景、空镜或不对应的普通餐桌不能替代。烟熏炉火、油腻摆盘、脏乱桌面和卫生疑虑为重点拒绝项。
- 交通：必须一眼识别正确交通类别。商务车可表现外观、内饰和座椅空间；游猎车可表现开顶或同等级车辆及观察/摄影场景；草原飞机可表现轻型飞机、登机、跑道或空中衔接；船只可表现船型、登船或航行。酒店大堂、机场大厅和纯风景不能替代工具主体，未保证品牌/型号不得形成承诺。
- 每日体验：优先当天核心活动、参与方式和与其他 DAY 不同的视觉记忆点。普通风景不能替代明确游猎、飞行、浮潜、文化参观、晚宴等活动；同日多图应分别承担 environment/action/detail/transition/closing 等不同角色。
- 复合体验：最多两图且各自有 `label`；例如外观与内饰、环境与餐食，只是帮助理解的结构示例。若 2000px 中任一主体不可辨认，应拆卡或只保留强项，并移除多余图片位后重排，不以留空或增加小图数量补偿。

## IMG-006—010 搜索规划、收集与记录细则

### 1. 应搜与不应单独搜索

- 图片蓝图优先规划封面、核心酒店/营地、有独立展示价值的特色餐饮、关键交通工具和每日核心体验；自费、可选、待确认体验按销售价值和事实依据参与规划，同时保留状态与费用边界。
- 普通早餐、午餐盒、普通酒店晚餐、无独立价值的接送/入住/退房/自由活动、与已有图片位表达相同的重复体验，以及原始行程未出现的推测体验，不独立建立搜索任务。
- 上述清单是规划优先级，不是“每类必须找到一张”的机械数量门槛；最终图片位数量与必要性分流服从IMG-003、FLOW-004，客户成品不得保留空白图片位。

### 2. 查询词生成

- 明确实体优先使用正式英文名，基础结构为“正式实体 + 准确地点 + 具体主体/活动 + 场景词 + official/gallery/press/media”。每个位置可规划 1—3 条英文查询，分别覆盖精准实体、真实场景和商业视觉；中文名只作补充。
- 禁止只搜“非洲旅游图片、豪华酒店、草原早餐、商务车图片”等宽泛词。查询必须能对应 slot 的地点/品牌/活动/主体，不能为追求好看移除硬事实。
- 参考示例（不构成事实）：`[Hotel Official Name] official pool deck gallery`、`[Destination] bush breakfast table official photos`、`[Transport Operator] light aircraft airstrip official`。方括号必须替换为本次已确认实体；不得直接复制示例中的地点或品牌。
- 第一轮精确，第二轮只放宽 `prefer` 或从理想镜头退回正确主体；`mustHave/forbid` 不得放宽。所有槽位最多两轮，高优先级也不恢复第三轮。

### 3. 来源与网页提取

- 来源顺序细化为：用户原始/已授权素材 → 运营方官网及官方媒体/press/gallery → 旅游局或目的地官方媒体 → 可信酒店联盟/行业组织 → 授权信息清晰图库 → 可信媒体/供应商 → 其他第三方。来源优先级只影响可信度和排序，不代替主体审核和商业授权。
- 官网身份按品牌官方域名判断；页面标题、URL 路径或正文出现品牌名不足以证明官网。官方社交媒体、联盟或媒体来源仍应记录平台、账号/页面和可追溯地址，不伪标官网。
- 网页提取优先 `og:image`、`twitter:image`、`srcset` 最大尺寸、懒加载字段、JSON-LD 的 image/photo/contentUrl 和正文中有明确 alt/title 的图片；排除 Logo、图标、头像、二维码、sprite、追踪像素、重复 URL 和无来源页的孤立图片。
- 技术硬门槛保持 IMG-009 的 900×500、14MB 和比例范围；排序时优先 1600px 以上，2400px 长边可作为正式大图素材偏好，但不得因未达到偏好而单独硬拒绝。

### 4. 低成本排序、审核与缓存

- 低成本排序优先官方/授权可信来源、页面主图、高分辨率、标题或 alt 命中主体以及适合槽位的横向比例；具体权重是程序实现参数，不升级成跨模块统一硬门槛。
- 初审统一比较 relevance、luxury、cleanliness、composition、watermark；终审先描述实际主体，再分别判断来源身份、地点/品牌、主体、硬拒绝与模块阈值。评分只用于自动采用和排序，不能替代 IMG-011 的三态证据判断。
- 搜索/页面候选缓存至少由标准化查询、地点和主体区分；图片文件以 SHA-256 去重；终审缓存至少包含图片哈希、模块、模型与 `mustHave/forbid` 规则指纹。地点、主体、硬规则、蓝图、模型或规则版本变化时，相关旧审核结果必须失效。
- 缓存用于减少成本和重复请求，不能默认跨项目复用同一成片，也不能覆盖用户锁定、最新事实和当前规则。

### 5. 去重与内部账本

- 文件相同用 SHA-256；缩放、压缩和轻裁切的近似图使用 dHash/pHash。当前程序 dHash 汉明距离 `≤ 8` 作为视觉近重复参数；同场景连拍、相似机位和跨模块同义画面仍需视觉复查。
- 每个下载候选的独立记录至少包含 record/candidate ID、slot、轮次、查询词、本地预览、原图、来源页/标题/类型、官网标记、许可/创作者（可得时）、尺寸、SHA/dHash、初审/终审分数、状态、阶段和理由。
- 失败记录至少包含 slot、实际查询、失败阶段、原因、尝试次数和下一动作；不得静默丢弃。来源与审核字段只在内部账本和编辑器候选详情使用，客户结果继续服从 IMG-020。

## 图片智能体用途与责任

- 任务规划：读取整程事实、视觉主线、真实 layout slots 和用户锁，决定哪些位置值得搜、优先级和不同视觉角色；不得创建新页面、改文案事实或覆盖锁图。
- 图片搜索：按 slot 输出查询、来源优先级、候选和失败记录；允许放宽软偏好，禁止放宽地点、品牌、主体、水印、下载安全和全局去重。
- 图片审查：输出三态、实际主体、来源/视觉分离判断、分项分数、理由和硬拒绝证据；系统异常转 manual，不推断图片有硬错。
- 生成后审查：在实际 2000px 中检查图文对应、重复、色调、顺序、裁切、双图职责和空白，只处理失败 slot，不重写整份行程。
- 失败动作：预算结束后可选位移除重排；封面、每个展示酒店和每个展示DAY的最低主图缺失时等待用户确认，未补齐不得100%进入编辑器。manual候选可保留，硬拒绝不可采用；授权不明不影响生成100%和编辑，但正式导出门禁保持关闭。产品已明确禁止AI生成图片兜底。
- 最终责任：程序负责 slot、预算、技术安全、三态、去重、锁定和客户隔离；AI 负责受限规划/排序/视觉判断；用户负责 manual 采用与自有素材；人工负责整体审美和商业授权。

## 图片位完成状态

每个图片位首次只执行一轮业务搜索和结构化审核；首轮未解决时，整批结果先交现有总规划与调度智能体判断，不得由图片审核器自动开启第二轮。智能体每个必需图片位最多指定一次定向补搜，必须改写搜索目标、复用搜索和视觉审核缓存，并且只审核新增候选。相同文件指纹、相同图片位和相同规则版本不得重复审核；定向补搜后仍无合格图时进入用户选择，必需位不得空白完成。

最终仍显示的图片位只有在自动采用真实本地图或已有用户锁定真实可用图片时才视为完成。最低必需位由程序按版本化配置确定：封面1张、每个展示酒店模块1张主图、每个展示DAY 1张主图；AI不能改写必要性，只能建议第二张、装饰图或细节图等可选增量。预算内搜索/终审失败后，可选位必须从客户版面移除并触发重排；最低必需位必须进入待用户确认，直到用户采用可用候选、上传已授权素材或受控重搜成功。`manual_review`候选可保存在候选库，但不能让缺少真实可用图片的必需位自动完成。任何客户预览或正式成品不得显示空白框、占位图、不合格图、硬拒绝图或AI生成图。
