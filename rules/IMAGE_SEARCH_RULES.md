# 奢游客户长图图片搜索与选片规则

> **历史迁移文件**：当前有效内容已与 `图片使用规范.md` 融合为 `04-图片搜索与使用规范.md`。本文件仅供迁移核对与历史追溯，不再作为当前执行依据；下文旧版独立人工审核页、97% 和 `manual_review` 清零门禁均已过期。

版本：1.3  
适用场景：将旅行行程、报价单或产品方案中的文字内容，转换为面向最终客户的高端旅行长图。  
目标：图片真实、准确、干净、高端、不重复，并控制搜索时间与模型调用成本。

> **v1.3 历史更新记录**：当时以 `audit/tasks/图片流程重构总任务书.md` 作为阶段实施依据。该任务书现已完成迁移，不再制定当前规则；当前图片流程唯一服从 `04-图片搜索与使用规范.md`。本文件后续人工确认门禁和 97% 条款仅保留为历史背景。

品牌调性、禁用图片和最终客户成品的通用要求以 `rules/图片使用规范.md` 为准；本文件负责图片槽位、搜索预算、并发、自动审核、人工确认和来源账本等管线规则。两份文件冲突时，地点、主体、水印、授权和客户信息安全等更严格的硬门槛优先。

## 1. 总原则

1. 必须先确定图片展示位，再开始搜索，禁止先搜一批图片后随意填充。
2. 每张图片必须明确证明相邻文案中的具体内容。
3. 地点、品牌和主体正确，优先级高于单纯“好看”。
4. 图片漂亮不能抵消地点错误、主体错误或文案不对应。
5. 没有合格图片时必须留空或进入人工补图，不得使用演示图、无关风景或相似对象顶替。
6. 全张长图不得重复使用同一张或视觉高度相似的图片。
7. 来源记录用于追溯，不代表已经获得商业使用授权；正式发布前应复核授权。

## 2. 搜索前建立图片槽位

每个图片展示位必须先生成一条独立的 `imageSlot`：

```json
{
  "slotId": "hotel-singita-sabora",
  "module": "hotel",
  "label": "Singita Sabora Tented Camp",
  "location": "坦桑尼亚塞伦盖蒂西部",
  "brand": "Singita",
  "subject": "营地真实住宿场景",
  "mustHave": ["必须是Singita Sabora真实场景", "主体必须是住宿或营地空间"],
  "prefer": ["优先帐篷外观", "优先复古庄园风格", "优先横向构图"],
  "forbid": ["其他Singita酒店", "普通草原风景", "动物特写代替酒店", "水印"],
  "imageCount": 1,
  "priority": "high"
}
```

### 2.1 必须搜索的槽位

- 封面主视觉：1张。
- 每家重点酒店或营地：至少1张。
- 每项确认存在的特色餐饮：1张；复合餐饮体验可用2张。
- 每种关键交通工具：1张；商务车外观与内饰可用2张。
- 每日行程中真正有展示价值的核心体验：每项1张。

### 2.2 不应独立搜索的内容

- 普通酒店早餐、普通午餐盒、普通酒店晚餐。
- 没有独立展示价值的机场接送、入住、退房、自由活动。
- 与已建立槽位表达相同的重复体验。
- 原始行程未明确出现、仅由模型推测的体验。

### 2.3 优先级

- `high`：封面、核心酒店、特色餐饮、核心产品卖点。
- `medium`：交通、重要每日体验。
- `low`：补充氛围和非必要体验。

搜索顺序必须从 `high` 到 `low`。达到项目图片预算后，停止低优先级搜索。

## 3. 图片要求的写法

图片要求必须拆成三个层级，禁止把所有理想元素写成硬性条件。

### 3.1 mustHave：硬性条件

只放不可妥协的事实：

- 正确国家、城市、保护区、酒店或餐厅。
- 正确活动和主体。
- 餐饮必须看到餐食、餐桌或真实用餐场景。
- 交通必须看到对应车辆、飞机、船只或舱内空间。

### 3.2 prefer：优选条件

用于排序，缺少时不直接淘汰：

- 日落、星空、河景、泳池、露台等氛围。
- 更符合高端品牌的构图、光线和服务画面。
- 横向画幅、主体位置适合版式裁切。

### 3.3 forbid：禁止条件

- 地点或品牌错误。
- 用普通风景代替酒店、餐饮、车辆或具体活动。
- 明显水印、媒体角标、网址、Logo覆盖。
- 画面脏乱、餐桌杂乱、低档或卫生观感不佳。
- 模糊、严重曝光异常、过度滤镜、过度压缩。
- 门头代替餐食，酒店大堂代替商务车，树木代替丛林早餐。

## 4. 搜索词生成规则

### 4.1 基础公式

```text
正式英文名称 + 准确地点 + 具体主体/活动 + 场景词 + official photos/gallery
```

优先使用官方英文名称。中文名称只用于补充，不应替代准确英文名称。

### 4.2 查询词示例

- 封面：`Tanzania Serengeti iconic luxury safari landscape golden hour`
- 酒店：`Singita Sabora Tented Camp official tent exterior gallery`
- 酒店泳池：`Singita Faru Faru Lodge official pool deck gallery`
- 酒窖：`Ritz-Carlton Masai Mara wine cellar private dining official`
- 丛林早餐：`Angama Mara bush breakfast table official photos`
- 星空晚宴：`Masai Mara starlit dinner outdoor table official`
- Carnivore：`The Carnivore Nairobi nyama choma dining food official`
- 草原飞机：`Coastal Aviation Cessna Caravan Tanzania safari airstrip official`
- 商务车：`Mercedes-Benz V-Class luxury van exterior interior official`
- 游猎车：`Tanzania open safari vehicle game drive official tourism`

### 4.3 禁止使用的宽泛查询

- `非洲旅游图片`
- `肯尼亚美景`
- `豪华酒店`
- `草原早餐`
- `商务车图片`

查询词必须包含具体对象，否则容易得到看似漂亮但无法证明文案的图片。

## 5. 来源优先级

按以下顺序搜索：

1. 酒店、营地、餐厅、航空公司、车辆品牌、旅游局官方网站。
2. 官方媒体中心、新闻图库、品牌官方社交媒体。
3. Virtuoso、罗莱夏朵等可信行业组织或酒店联盟页面。
4. 高端旅行媒体和可信目的地供应商。
5. Wikimedia Commons 等授权信息相对清晰的图库。
6. 其他第三方页面，仅在前述来源不足时使用。

官网身份必须根据域名白名单或品牌官方域名判断，不能因为页面标题、URL路径或正文出现品牌名就认定为官网。

## 6. 搜索预算与提前停止

为避免搜索大量结果却只有少量可用图片，每个槽位执行以下预算：

### 第一轮：精准搜索

- 使用1条最准确查询词。
- 最多获取5个来源页面。
- 每页最多提取12张图片。
- 技术过滤后最多下载12张候选。
- 基础排序后只保留前4张进入视觉初审。
- 只对初审前2名做单图终审。
- 第一张通过全部门槛后立即停止。

### 第二轮：降级搜索

仅当第一轮没有合格图片时执行：

- 放宽 `prefer`，不得放宽 `mustHave` 和 `forbid`。
- 查询词从特定构图退回到正确主体。
- 来源扩展到可信媒体和 Wikimedia Commons。
- 最多再下载12张候选。
- 同样只初审4张、终审2张。

### 停止规则

- 每个普通槽位最多执行2轮搜索。
- 每个高优先级槽位最多执行3轮搜索。
- 单槽位默认最长处理时间90秒。
- 达到预算仍无合格图片，记录失败原因并进入人工补图。
- 禁止无限换关键词搜索。

### 6.1 并发与统一决策

- 网页搜索、来源页图片提取、技术过滤和候选下载允许最多 `3` 个图片槽位并发执行。
- 并发单位是图片槽位；单个槽位仍必须独立遵守页面数、提取数、下载数、轮次和 90 秒预算，不能因并发扩大单槽位预算。
- 槽位必须先按 `high → medium → low` 排序；同优先级内保持原始版式顺序，不能按网络请求完成先后决定选片顺序。
- 并发阶段只负责收集和技术过滤候选，不得直接把先完成下载的图片写入成品。
- 视觉初审、单图终审、最终选片和全局去重必须在所有同批候选收集后，按确定的槽位顺序统一处理。
- 全局去重器必须由整次长图生成共享，禁止每个并发任务各自创建去重器。
- 第一张通过全部门槛后立即停止当前普通槽位的终审；多图槽位最多处理规则允许的前 2 名，并继续执行全局去重。
- 并发任务失败不得影响其他槽位；失败槽位按轮次规则进入降级搜索或人工补图，并完整记录阶段、原因和尝试次数。

## 7. 网页图片提取

优先提取：

- `og:image`
- `twitter:image`
- `srcset`中的最大尺寸图片
- `data-src`、`data-lazy-src`等懒加载图片
- JSON-LD中的`image`、`photo`、`contentUrl`
- 网页正文中具有明确`alt`或标题信息的图片

排除：

- Logo、图标、头像、二维码、Sprite、追踪像素。
- 重复URL。
- 无法确认来源页面的孤立图片地址。

## 8. 技术过滤

候选图片进入视觉审查模型前必须满足：

- 支持格式：JPEG、PNG、WebP。
- 最小尺寸：宽900px、高500px。
- 推荐尺寸：宽1600px以上。
- 单文件最大14MB。
- 宽高比介于0.65和3.2之间。
- 图片可正常解码且无严重损坏。
- 来源地址为公开HTTP/HTTPS地址。
- 不访问本机、内网或私有IP地址。

技术过滤应先执行，避免把模型调用浪费在低清图、图标和无效文件上。

## 9. 基础排序

视觉审核前先进行低成本排序。推荐基础分：

```text
官网来源                 +40
Wikimedia及明确授权来源   +24
页面og:image             +20
twitter:image            +12
高分辨率                 最高+20
搜索结果每后退1名         -2
alt/标题命中主体          +10
横向比例适合卡片          +5
```

只把基础分最高的4张交给视觉审查模型。

## 10. 第一轮视觉初审

把最多4张候选制作成编号拼版，统一比较：

- `relevance`：图文、地点、品牌和主体相关度。
- `luxury`：高端感、光线、构图和品牌气质。
- `cleanliness`：干净程度、卫生观感、杂物和视觉噪音。
- `composition`：是否适合目标卡片比例和裁切。
- `watermark`：是否存在水印、角标、网址或覆盖Logo。

初审只负责排序和快速淘汰，不直接写入成品。

## 11. 单张终审

只终审初审排名前2张。必须先描述图片实际主体，再判断是否可用。

### 11.1 硬性通过条件

- `pass = true`
- `subjectMatch = true`
- `placeMatch = true`，或来源与画面足以支持该地点/品牌。
- `watermark = false`
- 不命中任何 `forbid` 条件。

### 11.2 自动通过参考门槛

- `relevance >= 80`
- `cleanliness >= 75`
- `luxury >= 72`
- 建议新增：`composition >= 70`

这些分数用于判断是否可以 `自动通过`，不是统一的硬拒绝线。未达到某项参考分数、但没有命中硬性拒绝条件的候选，必须进入 `待人工确认` 或继续与同槽位候选比较，不能直接从候选库中删除。

### 11.3 必须拒绝的情况

- 要求车辆但图片是酒店或望远镜。
- 要求餐食但图片只有门头。
- 要求酒窖但图片只是普通客房或餐厅。
- 肯尼亚图片冒充坦桑尼亚，或其他酒店冒充目标酒店。
- 画面脏乱、卫生观感差、低档、明显水印。

### 11.4 三态审核结果

每张进入视觉审核的候选图必须形成以下一种状态：

- `auto_approved` / 自动通过：满足硬性条件并达到对应模块的自动通过标准，可以直接参与全局去重与最终分配。
- `manual_review` / 待人工确认：没有明确硬伤，但场景不是首选、来源或地点判断存在不确定性，或奢华度、构图和偏好分数未达到自动通过标准。
- `hard_rejected` / 明确拒绝：命中 `forbid`、主体完全错误、明确地点或品牌错误、明显媒体水印、破图、低分辨率、严重低质或全局重复。

初审和终审不得静默丢弃候选。每张候选必须保留状态、来源、评分、判断理由和所处审核阶段。

### 11.5 模块化审核口径

- 封面：目的地辨识度、画质、构图和标题承载能力为核心；不默认要求证明某一家酒店。
- 酒店：酒店身份和来源可靠是硬条件；外观、客房、大堂、泳池、花园、餐厅和水疗等真实高品质空间均可使用。只有客户文案明确承诺某项设施时，具体设施才进入 `mustHave`。
- 特色餐饮：用餐类型和真实用餐环境必须匹配；香槟、特定菜品和仪式细节只有在原始事实或客户文案明确出现时才进入 `mustHave`，否则属于 `prefer`。
- 交通：交通工具类别必须正确；品牌、型号和内饰只有源数据明确保证时才进入 `mustHave`。
- 每日体验：活动主体必须正确；普通风景不能替代明确的游猎、飞行、渡河、潜水或晚宴。

可信官方来源和视觉主体必须分别判断。模型不得只凭建筑风格、山形或主观印象，推翻能够支持酒店身份的官方来源；当来源可信、主体属于目标酒店但场景不是首选时，应进入 `manual_review`，而不是 `hard_rejected`。

### 11.6 进入编辑器前的人工确认

当任一图片槽位没有自动通过图片、但存在 `manual_review` 候选时，生成流程必须进入图片人工确认步骤，并保持编辑器入口不可用。

人工确认页必须展示：候选缩略图、来源页面、官方来源标识、主要评分、待确认原因和已知风险，并允许用户执行：

- `采用此图`
- `拒绝此图`
- `本图片位留空`
- 上传已确认且具备使用权的本地素材

人工采用必须记录决定时间、原始审核状态和风险，不得伪装成自动通过，也不得被后台轮询、重新分配或后续渲染覆盖。

明显媒体水印、主体完全错误、明确地点错误、破图、低分辨率和全局重复图不提供直接采用入口。用户如拥有无水印或已授权版本，应上传替代文件。

只有所有图片槽位均形成最终结果，且 `manual_review`、搜索中、审核中和分配中的数量全部为零，生成任务才能达到 100% 并允许进入编辑器。图片位可以在搜索与审核结束后明确留空；留空属于已完成状态，不等于必须继续无限搜索。

## 12. 全局去重

去重范围必须覆盖整张长图，而不是只覆盖当前模块。

1. 使用SHA-256识别完全相同文件。
2. 使用dHash或pHash识别缩放、压缩、轻微裁切后的视觉重复。
3. dHash汉明距离小于等于8，默认判定为视觉重复。
4. 同一场景的连拍图即使哈希不同，也应通过视觉审核避免连续使用。
5. 复合卡片中的多图必须分别承担不同信息，不得只是同一画面的近似角度。

## 13. 复合体验与多图规则

只有以下情况可以使用多图：

- 商务车需要同时展示外观与内饰。
- 特色餐饮需要同时展示环境与具体餐食。
- 酒店需要同时展示建筑/景观与客房/泳池，且版式明确允许。
- 一个复合体验确实包含两个不同主体。

多图必须满足：

- 每张图承担不同信息。
- 来源和主体均准确。
- 色调与画面质量协调。
- 不得为了填满版式而增加无关图片。

## 14. 版式适配

- 封面优先横向宽幅，主体不应压在标题区域。
- 酒店卡片优先建筑、泳池、客房或核心体验，不用普通景观代替。
- 餐饮卡片必须能看到具体餐食、餐桌或真实用餐服务。
- 车辆外观图优先使用`contain`，不得严重裁掉车头或车身。
- 人像、动物和车辆应根据主体位置保存裁切焦点。
- 奇数卡片时，应把最具产品价值且图片质量最高的一项设为重点大图，不能随机放大。

## 15. 缓存规则

为减少重复搜索：

- 按“标准化查询词 + 地点 + 主体”缓存来源页面和候选图片。
- 同一家酒店在不同项目中可复用候选库，但不能默认复用同一成片图片。
- 已下载图片按SHA-256缓存，避免重复下载。
- 视觉审核结果按图片哈希和槽位要求缓存。
- 当 `mustHave` 或 `forbid` 变化时，旧审核结果必须失效。

## 16. 失败处理

搜索失败时必须记录：

```json
{
  "slotId": "hotel-example",
  "query": "实际使用的搜索词",
  "stage": "search|extract|download|audit|dedupe",
  "reason": "没有官网图片通过主体与质量终审",
  "attempts": 2,
  "action": "manual_upload_required"
}
```

失败后：

- 成品中保持空位、隐藏该图片位或调整版式。
- 明确提示人工补充已授权素材。
- 不使用演示图片自动补位。
- 如果仍有未命中硬性拒绝条件的候选，将其保留为 `manual_review`，不得以“没有自动通过图片”为由全部删除。

## 18. 推荐执行流程

```text
读取行程事实
→ 建立图片槽位
→ 为每个槽位定义mustHave/prefer/forbid
→ 按优先级排序
→ 生成第一轮精准查询
→ 最多3个同优先级槽位并发搜索，每槽位最多5个来源页面
→ 并发提取、技术过滤和候选下载
→ 基础排序取前4张
→ 按固定槽位顺序统一拼版视觉初审
→ 按固定槽位顺序单图终审前2张
→ 候选写入自动通过、待人工确认或明确拒绝三态
→ 第一张自动通过后停止当前普通槽位的继续终审
→ 使用整次生成共享的去重器执行全局哈希与感知去重
→ 没有自动通过图但有待确认候选时进入人工确认
→ 人工采用、拒绝或明确留空
→ 所有图片槽位形成最终状态后写入对应版式
→ 记录来源账本
→ 失败槽位进入第二轮或人工补图
→ 待确认、搜索中、审核中和分配中全部清零后生成任务达到100%
→ 允许进入编辑器
```

## 19. 最终验收清单

- [ ] 每张图都能明确对应旁边的文案。
- [ ] 酒店、餐厅、交通和体验没有互相错配。
- [ ] 国家、地区和品牌没有张冠李戴。
- [ ] 餐饮图片展示具体餐食或真实用餐场景。
- [ ] 所有图片清晰、干净、高端，无脏乱观感。
- [ ] 没有明显水印、媒体角标和网址。
- [ ] 全图没有原图重复和视觉近似重复。
- [ ] 多图卡片中的图片承担不同信息。
- [ ] 图片裁切没有切掉核心主体。
- [ ] 所有最终图片都有可追溯来源记录。
- [ ] 不合格槽位没有被演示图或无关图片自动填充。
- [ ] 每张进入审核的候选都有自动通过、待人工确认或明确拒绝状态，没有静默丢失。
- [ ] 首选场景、构图和未被文案承诺的装饰元素没有被错误当成硬门槛。
- [ ] 所有待人工确认图片已被采用、拒绝、替换或明确留空。
- [ ] 所有图片槽位形成最终状态前，编辑器入口保持不可用。
