# 组件规范

> **历史迁移文件**：当前有效内容已迁入 `05-模板版式与品牌资产.md`，运行与证据边界迁入 `06-技术运行与文件保存.md`。本文件仅供迁移核对与历史追溯，不再作为当前执行依据。

完整组件注册表见 `components/component-registry.json`，共 26 类。所有组件读取 `config/design-tokens.json` 的颜色、栅格、间距、圆角、描边、阴影和字号体系。

关键确定性规则：

1. `days.length` 决定 DAY 数量，DAY 标题与正文设置 `break-inside: avoid`。
2. 酒店、用车、司机、导游标签逐项过滤空值，使用 flex 自动回流。
3. `spots.length` 为 0/1/2/3/4 时分别调用无图、单图、双图、三图、四图网格。
4. 正文不缩小字号；容器高度随内容增长。
5. 费用、退改、收款、注意事项按字段有无整块隐藏。
6. 相同 JSON、浏览器版本、字体与资源会生成相同版式。
7. 酒店、特色餐饮、交通等双列卡片遇到奇数时，不自动放大最后一张；只有数据对象显式设置 `layout: "wide"`，或经过内容判断确认为核心卖点时，才使用跨两列重点卡。
8. 如果奇数卡片组没有明确重点，采用居中普通卡、三栏或其他平衡版式消除空白，不制造错误视觉重点。
9. `layout: "wide"` 表示内容拥有更高视觉权重，必须用于真正值得强调的酒店、餐饮、交通或体验；平级信息类模块如注意事项不因单数而放大某一条。
10. 图片默认使用 `object-fit: cover`；当 `image.fit` 或 `images[].fit` 为 `contain` 时，组件必须完整显示图片主体，适用于商务车拼图、内饰组合、房间结构、餐饮细节等需要看清的素材。
11. 定制师名片根据内容自适应高度：仅有头像、姓名、身份和服务文案时使用紧凑版；只有真实提供从业时间、成交单量、客户好评等可核验数据时，才显示并预留底部表现指标区。
12. 复合体验卡支持 `images` 双图模式，最多两张；每张图必须提供对应子体验 `label`。2000px 成品中任一图片不可辨认时，数据层应拆卡或回退为单图，不继续缩小图片。
13. 标准客户交付只生成 2000px 高清版；1080px 仅作为特殊渠道需要时的可选输出。
14. 任意模块隐藏字段、指标或卡片后必须自动收缩高度，不得为不存在的内容保留固定空白；只有同一行卡片需要视觉比较时才统一最小高度。

图标来自 Tabler Icons 官方 SVG 库，统一为 2px 线宽、圆角端点与 `#B28B33` 色彩规则；模板通过 CSS mask 着色，不修改源 SVG。
