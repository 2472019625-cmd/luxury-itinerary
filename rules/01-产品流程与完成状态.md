# 01 产品流程与完成状态

版本：1.11
生效日期：2026-09-07
适用范围：从资料上传到编辑、导出、执行交接与独立审查的产品流程和完成状态。数据、文案、图片、视觉和运行细则分别服从 02—06。

## 执行类型

- `A 程序强制`：确定性流程或状态门禁。
- `B AI生成`：模型承担的文案或视觉策划阶段。
- `C 生成后检查`：生成、放置或渲染后的质量检查。
- `D 人工验收`：业务、授权、审美或独立复核。

## Simple Skill Pipeline 适用边界

`simple-skill-pipeline` 使用 Planner → Copy/Image Skills → Program/Renderer 最小职责链，不启用 `review_decision`、finding package、多层 Reviewer、Reviewer 发现问题后自动重生成、图片自动第二轮搜索、自动定向重搜或 stage budget 驱动业务流程。下文仍出现这些名称的旧执行说明只保留为 `shadow-planner` 历史范围，不适用于新执行器；内容事实、完成状态、图片必要性、客户隔离和导出安全规则继续有效。

新执行器默认按最小责任单元处理失败：单个 DAY、酒店图片位或可选模块失败只记录该单元并允许无依赖任务继续；未解决的必需问题可以阻止最终 100%，但不能阻止其他可执行任务先完成。只有主输入无法解析、核心事实结构无法建立、关键事实/费用发生无法继续的冲突、项目保存系统失败，或其他确实使所有后续任务无法继续的项目级错误，才中断整条链。

编辑器同时承担“完成后调整”和“局部问题收尾”两种用途。输入与核心事实结构有效时，局部文案失败、必需图片未找到或单项审核服务异常必须先形成 2000px 可编辑草稿，并在编辑器集中提醒对应酒店、DAY或图片位；这些问题仍阻止100%和正式导出。草稿可编辑不等于生成完成，也不得用空白、不合格图片或缺失必需内容伪装正式成品。

## 异常状态分类

审核发现业务语义问题时，用户流程统一为“审核只报告 → 同批问题由总智能体判断 → 程序校验并执行目标动作 → 只复查改变目标”。页面应区分审核中、智能体判断中、目标处理中和等待用户确认；审核结果本身不得直接触发整模块重生成、整批重搜或完成状态。

- 事实或费用冲突：按 02 阻止生成或返回用户确认。
- 普通品牌表达建议：按 03 以一个 DAY、酒店或小模块为单位有限局部重写；用户明确接受剩余建议后记为 `user_accepted_suggestion`，保存问题/规则ID、决定与时间，可作为智能体完成的允许终态，但不标 `passed`。
- 事实、费用、履约、安全、内部信息和核心结构的项目级致命错误：阻止草稿渲染并进入对应失败/确认状态。局部文案或必需图片问题：允许进入带提醒的可编辑草稿，但不得用文案改写或 `user_accepted_suggestion` 绕过，未解决前不得100%或正式导出。
- 系统或外部服务异常导致任务无法形成可解释结果：进入“生成失败”，保留任务证据和可重试入口。
- 图片无合格结果：按04区分必需与非必需视觉位；非必需位从客户版面移除并重排，必需位进入待用户确认，可单位置重搜、选择可采用候选或上传已授权素材，不得用空白或不合格图片完成。
- 商业图片授权：与生成100%分开；授权待确认时可进入编辑器且生成状态保持完成，正式导出必须由用户确认权利或采用管理员预先批准素材。拒绝授权时替换图片、补充授权或停止导出，不回退重生、重审或98%。
