# Excel 字段到模板组件映射说明

> **历史迁移文件**：当前有效内容已迁入 `02-数据事实与字段映射.md`，显示与模块边界迁入 `03-品牌文案与模块内容.md`、`05-模板版式与品牌资产.md`。本文件仅供迁移核对与历史追溯，不再作为当前执行依据。

建议工作簿包含 `基础信息`、`每日行程`、`费用与政策` 三张表。字段名保持下表一致；每日行程每行代表一天，景点可用 JSON 数组或拆成景点1—4字段。

| Excel 字段 | JSON 路径 | 模板组件 | 空值规则 |
|---|---|---|---|
| 行程名称 | `title` | 封面/行程主标题 | 必填；客户版需重写为“目的地 + 天数晚数 + 定制游属性 + 主题”，不直接套原始表格标题 |
| 行程副标题 | `subtitle` | 封面副标题 | 空值隐藏；不使用酒店清单堆叠，需写成体现定制节奏、路线画面和核心体验的一句话 |
| 目的地 | `destination` | 封面/主视觉说明 | 必填 |
| 出行人数/成人数/儿童数 | `travelers/adults/children` | 出行信息卡 | 儿童为0不显示括注 |
| 出发日期/返回日期 | `startDate/endDate` | 日期信息卡 | 必填，YYYY-MM-DD |
| 行程天数 | `dayCount` | 天数卡 | 可由 `days.length` 自动计算 |
| 定制师姓名/头像/职位/电话/工作微信/介绍 | `designer.name/avatar/role/phone/wechat/bio` | 定制师名片 | 资料由应用端配置；电话完整展示，工作微信允许自由文本；单项为空时隐藏，两项均为空时联系方式行隐藏；身份空值时显示默认头像与“定制师名字 \| 资深定制师”占位，不编造联系方式 |
| 原始海报亮点 | `sourcePosterHighlights[]` / 转写进 `highlights[]` | 产品亮点 | 原始资料如有海报下方亮点，优先抽取并扩写 |
| 产品亮点 | `highlights[]` | 产品亮点 | 需包含奢游可复用服务价值 + 原始海报亮点/本行程独有卖点；空数组隐藏 |
| 每日日期/城市/餐食 | `days[].date/city/meals` | DAY标题、信息行 | 餐食为空隐藏 |
| 每日酒店/用车/司机/导游 | `days[].hotel/vehicle/driver/guide` | 服务标签 | 各自独立隐藏，不留空位 |
| 每日行程描述 | `days[].description` | 行程信息行 | 必填，高度自适应 |
| 景点名称/介绍/图片 | `days[].spots[]` | 0—4图版式 | 单体验用 `image`；复合体验可用 `images`，最多2张且每张填写对应子体验 `label` |
| 特色餐饮标题 | `diningSectionTitle` | 特色餐饮 | 客户版固定为“特色餐饮” |
| 特色餐饮 | `diningExperiences[]` | 特色餐饮 | 只放特色餐饮/代表性餐厅/用餐场景；复合餐饮体验可用 `images` 双图并逐图填写 `label` |
| 重点版式 | `*.layout` | 酒店/特色餐饮/交通卡 | 仅核心卖点或需要大图识别时设为 `wide`，不因奇数机械放大 |
| 图片裁切 | `image.focus/images[].focus` | 图片卡 | 默认 `50% 50%`，按主体调整 |
| 图片适配 | `image.fit/images[].fit/days[].spots[].fit/days[].spots[].images[].fit` | 图片卡 | 默认 `cover`；拼图、车辆内外饰组合、房间/餐饮细节图可用 `contain` |
| 行程总价 | `totalPrice` | 费用总价 | 空值隐藏 |
| 报价说明 | `priceNotes[]` | 费用说明 | 放客户可见的有效期、补差和最终确认说明；不放内部测算逻辑 |
| 费用包含/费用不含 | `included[]/excluded[]` | 费用卡片 | 空数组隐藏 |
| 退改政策/注意事项 | `cancellation[]/notes[]` | 政策/提示卡 | 空数组隐藏；注意事项默认覆盖行程节奏、气候穿着、活动安全、自然现象、证件财物行李、特殊需求 |
| 收款信息 | `payment.*` | 资金安全/收款卡 | 对象为空隐藏收款卡 |
| 联系方式 | `contact.*` | 品牌落款 | 空字段逐项隐藏 |

数据校验以 `config/itinerary-schema.json` 为准。生产接入 Excel 时，应先转为该 JSON 结构，再交给渲染器。
