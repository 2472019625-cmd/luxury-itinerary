# 智能体规则与能力调度规范

版本：1.1-draft

日期：2026-09-02

状态：产品决定已写回，待独立复核
适用范围：新智能体试验流程；第一阶段影子规划只输出计划，不调用真实能力

## 一、这份规范解决什么问题

系统不把 01—06 全文每次塞给模型，也不允许模型自行决定跳过规则。本规范把一次生成拆成受控任务，并规定“任务类型—规则卡—能力—输入输出—依赖—失败动作—用户状态”的固定关系。

01—06 仍是内容规则唯一来源。本文件只做规则编号加载、能力权限和新智能体适用范围配置，不复制或改写第二套内容规则。程序行为、旧固定流程和历史证据都不能反向成为新规则。

## 二、适用范围和版本隔离

### 2.1 两套流程不能混用

| 项目 | 旧固定流程 | 新智能体流程 |
|---|---|---|
| 开发与数据 | 冻结基线及原固定流程目录 | `D:\奢游\行程单报价单\奢游行程单美化-智能体试验区` |
| 规则配置 | 冻结基线版本 | 任务启动时固定的 `ruleProfileVersion` |
| 完成与编辑器 | 保留旧流程 98% 修订/预算结束可缺图行为 | 全部必需任务明确终态后 100% 才进入编辑器 |
| 图片 | 旧流程可按冻结行为留空 | 最终实际显示图片位不得留空；非必需位移除重排，必需位等待确认 |
| 入口与端口 | 原入口、4173 | 独立入口，默认 `127.0.0.1:4174`；冲突时选择受控其他本地端口并记录实际值，禁止占用或误连4173 |
| 项目状态 | 旧流程项目 | 独立项目、任务、证据和完成状态 |

单个项目创建时写入 `flowKind=agent_v1`、规则/能力/提示词版本和项目 ID，之后不得切换流程或引用另一流程的完成状态、缓存、项目数据或浏览器数据。

### 2.2 本批与下一批

本批只交付规范、覆盖表、冲突清单和实现输入。下一批才可建立 JSON 配置、schema、计划校验器和影子规划器。影子规划器阶段所有能力均为 `plan_only`：它可以声明将来要调用的能力，但不得真正生成文案、联网、搜图、放置或导出。

### 2.3 正式规划模块与唯一计划来源

影子阶段建设的是最终智能体架构中的正式规划模块，不是以后废弃的独立工具。每个规划记录只保存一份通过校验的结构化项目计划；“查看本次规划”页面从该计划确定性生成普通语言展示，未来执行器也读取同一计划引用，不得复制、转换或另存一套展示计划。重新规划创建新的不可覆盖记录，并由项目的 `activePlanId` 指向最新通过校验的计划。当前 `executionEnabled` 必须固定为 `false`，除确定性解析和 `trip_planner` 外其他能力真实调用次数为零。

T01—T20只是规则覆盖和阶段安全检查点，不是智能体必须原样输出的20条展示任务。`trip_planner` 根据当前事实自主生成动态任务图；校验器只验证、给出具体错误并允许一次目标结构修正，不能用固定任务模板替换计划。正式员工版本永久保留“查看本次规划”作为可选查看，不要求每次批准；资料完整时未来执行器可在计划通过后自动继续，只有事实、费用、履约或安全选择进入用户确认。

## 三、四层规则加载

| 层 | 内容 | 谁提出 | 谁强制 | 缺失时 |
|---|---|---|---|---|
| L1 全局硬规则 | 事实优先、确定性字段保护、客户/内部隔离、不得改变产品安排、禁用 AI 正式图片、预算上限、100%门禁、取消和项目隔离 | 规则配置固定 | 程序 | 计划无效，不能执行 |
| L2 任务必需规则 | 按 `taskType` 固定映射的规则卡 | 路由配置 | 程序 | 计划无效；只允许补回缺失规则后重校验 |
| L3 条件与模块规则 | 餐饮、自费、儿童长者、草原飞机、海上活动、签证时效等，仅在事实命中时启用 | 智能体可从白名单提议 | 程序校验条件并加入 | 非法/不适用 ID 删除并留下校验错误；不得用它改变事实 |
| L4 最终检查规则 | 事实、文案、图片、版式、客户隔离和完成门禁 | 路由配置 | 独立检查器或人工 | 返回目标任务、等待确认或生成中断；不得整份重写掩盖问题 |

规则快照在项目创建时冻结。任务只接收自己的完整规则卡和必要上下文，不读取全部 Markdown。智能体不能删除 L1/L2、替换规则正文、引用不存在的 ID，或调用规则未授权的能力。

### 3.1 L1 固定集合

新智能体 L1 至少包含：`FLOW-001/002/004/007/009`、`DATA-001/004/005/007/008/010/011/012/013`、`COPY-002/011/014/017`、`IMG-001/008/009/011/012/016/019/020`、`VIS-003/016`、`OPS-004/005/006/010/011/012/013`。其中 98% 和旧目录/4173 只作为适用范围差异记录，不作为新智能体运行值；具体冲突见配套清单。

## 四、受控能力目录

预算均指管理员发布的 `capabilityConfigVersion` 内上限；计划只能引用预算键，不能写入或突破真实费用配置。`可改`之外的字段一律只读。

| 能力 ID | 允许输入 → 允许输出 | 可改 / 禁改 | 推理与预算 | 失败、重试、证据、用户状态 |
|---|---|---|---|---|
| `source_parser` | 单份受支持主 Excel；补充资料只允许可提取文本的 PDF、DOCX、TXT、Markdown 和用户授权图片 → 结构化事实、来源覆盖、未映射项 | 可改解析草稿；禁改确认事实、客户文案；补充资料不得覆盖 Excel 或用户确认事实 | 程序/最低；1 次解析+1 次格式修复；影子阶段只记录类型/来源/用途不解析 | 文件/格式/字段错误；提取失败要求粘贴文字或可读文件，不做OCR或猜测；保存源指纹、单元格去向；正在准备或等待确认 |
| `fact_validator` | 事实快照、覆盖台账 → 冲突、缺失、费用/履约/安全结果 | 可改检查结果；禁改事实答案 | 程序；每次输入指纹 1 次 | 目标字段复检 1 次；保存逐项证据；等待确认或生成中断 |
| `human_confirmation` | 仅业务选择项及来源 → 用户决定、时间、影响字段 | 只写确认记录；禁改无关字段 | 人工；集中 1 轮，后续仅新异常 | 用户取消/未回答不重试；保存选择与来源；等待确认 |
| `trip_planner` | 已确认事实、固定骨架、条件命中 → 内容主线、视觉主线、任务图 | 可改规划字段；禁改事实、模块骨架、完成条件 | 高；1 次+结构修正 1 次 | JSON/覆盖/越权失败；保存输入指纹与计划差异；正在生成 |
| `web_fact_search` | 已有行程实体、待核验字段、来源规则 → 结论、URL、核验日期、有效期、内部建议 | 只补证据/建议；禁改行程、费用、采用状态 | 中；每字段预算；不因无结果无限扩搜 | 网络/无权威/来源冲突；最多 1 次替代来源；保存引用快照；等待确认或保守表达 |
| `copy_writer` | 模块事实、规则卡、必要前后文 → 目标字段/DAY 文案及事实引用 | 只改客户表达字段；禁改确定性字段和非目标模块 | 普通低/中，复杂 DAY 高；每单元 1 次 | 空/截断可机械重试 1 次；保存输入输出与依据；正在生成 |
| `brand_reviewer` | 最终合并文案、逐规则检查卡 → 路径化问题清单 | 只写审查结果；禁改正文、事实 | 高；最终合并后 1 次 | 服务失败 1 次；保存问题路径、规则、严重性；自动修复中/生成中断 |
| `target_patcher` | 单个问题、目标事实、原值、规则卡 → 最小补丁 | 只改命中字段/酒店/DAY；禁改其他路径和事实 | 明确润色低；复杂目标高；低到高最多升级 1 次 | 每目标低 1+高 1；保存前后值、规则和复检；自动修复中或等待确认 |
| `image_blueprint` | 主线、事实、真实 slot、锁图和程序已判定的必要性 → 角色、搜索卡、可选增量建议 | 只改蓝图；必要性只读；禁改事实、文案、锁图、URL及必需/可选属性 | 中，复杂整程高；1 次+结构修正 1 次 | 未知/重复 slot、试图改必要性或其他越权即拒绝；保存版面/输入指纹；正在生成 |
| `image_search` | 经校验搜索卡、来源白名单、预算 → 候选、下载、来源和失败记录 | 只写目标 slot 候选；禁改硬条件、其他 slot、锁图 | 低/程序；服从 `IMG-008` | 每 slot 最多 2 轮；保存查询、来源、下载与错误；正在生成/等待确认 |
| `visual_auditor` | 可解码候选、slot 规则、相邻文案 → 三态、主体描述、分项判断 | 只写审核结果；禁改图片/文案/事实 | 中；独立队列 2，稳定后最多 3 | 超时/429/5xx/非法 JSON 转 `manual_review`，不算硬拒绝；最多 1 次技术重试；保存证据；正在生成 |
| `layout_renderer` | 通过采用门禁的客户数据、固定模板资产 → 2000px 预览和版面测量 | 只写渲染产物；禁改事实、文案含义、图片资格 | 程序；目标版面最多 1 次重渲染 | 破图/溢出/资产失败；保存尺寸、哈希、测量；自动修复中/生成中断 |
| `final_qa` | 最终事实、文案、图片账本、实际 2000px → 分域结果和完成门禁 | 只写 QA/状态；禁改内容 | 程序+独立检查+人工项；1 次，目标修复后复检 | 失败返回最小责任单元；保存逐规则证据；等待确认/自动修复/生成中断 |
| `project_store` | 项目、任务、证据、版本、统计 → 原子化保存引用 | 只写当前项目命名空间；禁写旧流程或其他项目 | 程序；每次状态变化 | 写入失败最多 1 次；保存校验和/时间；生成中断 |
| `task_cancel` | 当前项目、运行中调用清单、二次确认 → 已取消状态和取消结果 | 只取消当前项目未完成调用；禁删项目、伪造退款/完成 | 程序；1 次幂等操作 | 保存无法终止的调用与已发生费用说明；用户状态已取消 |

所有能力配置还必须带 `allowedInputSchemas/allowedOutputSchemas/mutablePaths/forbiddenPaths/reasoningPolicy/budgetKey/failureTypes/retryLimit/evidenceSchema/userStateMap`。计划引用未发布能力、字段越界或预算键缺失时直接校验失败。

## 六、依赖、并行和缓存

1. T04/T05 未形成确定事实快照前，T06、T09、T12 不能把未确认事实写入客户结果。
2. T06 完成后，不依赖最终文案的 T12—T14 可与 T09 并行；T15 必须等待最终文案和图文一致性。
3. T08 按字段设依赖边：酒店 A 的证据只阻塞酒店 A 文案，不阻塞酒店 B、费用或无关 DAY。
4. DAY 文案按连续 2—3 日单元提供必要前后文；跨日差异检查可读取相邻摘要，但不得一次重写全部 DAY。
5. T10 对最终合并结果执行一次品牌审查；问题进入 T11，不重复生成未命中模块。
6. T13 与 T14 使用连续队列：候选一旦下载即审核，不等待全量搜索结束。
7. 缓存键至少包含 `inputFingerprint + ruleProfileVersion + capabilityConfigVersion + promptVersion + targetPath`。任一输入或规则变化只使相关单元失效。
8. 任何失败只重试目标单元。只有项目级版本/事实骨架变化才允许重建计划；完整重新生成必须创建新项目。
9. T18 等待所有必需任务处于 `succeeded/user_resolved/user_accepted_suggestion/not_applicable/removed_optional` 等允许终态；`user_accepted_suggestion` 只用于普通品牌表达且不等于passed。`failed/running/cancelled/awaiting_required_image/blocked_fact` 均不能通过生成门禁；`awaiting_export_rights` 不影响100%和编辑器，但阻止正式导出。

## 七、推理、预算和升级

- 高：T06 整程主线、复杂 DAY、跨日差异、T10 最终品牌审查。
- 中/低：普通模块、结构清楚的连续 DAY、搜索卡、明确目标润色。
- 最低/程序：字段提取、格式、schema、硬门禁、技术检查、机械重试。
- 低/中失败且该能力允许升级时最多升高一次；结构/网络机械失败不得用高推理掩盖。
- 事实、安全、费用、履约检查没有“为提速跳过”的预算选项。
- 标准 7—10 日完整执行目标为 20 分钟以内；每阶段记录排队、运行、重试、调用次数和预算消耗。超时显示具体任务并按失败策略处理，不伪装完成。

## 八、计划字段定义

结构化计划是项目内唯一计划来源，页面和未来执行器共享同一 `planId`。展示层只能对其字段做确定性映射，不得调用模型补写另一份解释。计划至少在项目级包含 `planId/projectId/planVersion/previousPlanId/flowKind/executionEnabled/status/inputFingerprint/createdAt/validatedAt/summary/tasks/checkpointCoverage/confirmations/validation/adjustments/capabilityCallStats`；任务级字段如下。

| 字段 | 约束 |
|---|---|
| `taskId/taskType/targetPath` | 项目内唯一；类型在路由白名单；目标必须落在能力可改路径 |
| `ruleProfileVersion/capabilityConfigVersion/promptVersion` | 必填且与项目快照一致；任务中途不可漂移 |
| `requiredRuleIds/optionalRuleIds` | 必需集合必须完整；可选 ID 必须白名单且条件成立；不得重复 |
| `capabilityId/reasoningLevel` | 能力已发布且授权任务类型；推理符合能力策略 |
| `inputRefs/outputSchema` | 只引用当前项目已存在结果；输出 schema 已发布 |
| `dependsOn/parallelGroup` | 依赖无环；并行组不得突破事实/采用/完成门禁 |
| `timeout/retryLimit/costBudget` | 引用管理员预算键；不得超过能力上限 |
| `failurePolicy/userConfirmationPolicy` | 必须给出目标重试、降级、确认或中断；确认只用于业务选择 |
| `status/progressLabel` | 内部状态与用户七态映射；进度来自真实任务计数 |
| `inputFingerprint/resultRef/evidenceRefs` | 可恢复、可审计；未运行时 result/evidence 为空 |

## 九、计划校验和失败闭环

影子计划输出后，确定性校验器依次检查：schema → 版本一致 → 任务类型和能力授权 → L1/L2 覆盖 → L3 条件 → 可改路径 → 依赖无环 → 并行门禁 → 预算/重试 → 用户状态映射。任何一步失败，计划状态只能是 `planning_failed` 或返回目标规划修正；不得调用真实能力。

失败分类固定为：`input_invalid`、`rule_coverage_missing`、`capability_unauthorized`、`schema_invalid`、`fact_conflict`、`business_confirmation_required`、`external_unavailable`、`budget_exhausted`、`quality_failed`、`render_failed`、`storage_failed`、`cancelled`。每类必须映射到“目标重试、保守降级、等待确认、生成中断、移除非必需位或已取消”之一，并保存原始错误和下一动作。

## 十、完成门禁和用户状态

用户只看：正在准备、等待确认、正在生成、自动修复中、生成完成、生成中断、已取消。内部可有细状态，但不能展示模型推理正文。

新智能体进入编辑器的必要条件是：事实与费用硬检查通过；所需联网事实有证据或规则允许的保守表达；文案问题已通过、目标修复或被用户明确接受为普通表达建议；所有实际显示图片位有可采用真实图片；必需视觉无等待项；实际 2000px 渲染和最终 QA 通过；客户结果无内部信息；所有必需任务有允许终态。满足后一次性写入 100% 和生成完成。

取消需二次确认，尽力停止未完成调用，保存已发生费用说明，状态写为已取消；项目和原始资料保留。已取消项目不能继续、进入编辑器或导出。基于旧项目完整重生时复制原始资料创建新项目，不覆盖原项目。

编辑器属于完成后的人工区。普通手动修改不调用 AI、不自动改回；主动局部 AI 必须显示建议或前后对比并由用户应用。商业授权与生成完成分开：来源追溯不等于权利确认；授权待确认时可编辑且保持100%，但正式导出必须由用户确认权利或使用管理员预先批准素材。拒绝授权时替换、补充授权或停止导出，不回到生成、复审或98%。

## 十一、影子阶段证明标准

第一阶段不证明能力执行效果，只证明计划安全可执行：

- 每个计划任务字段齐全，L1/L2 无遗漏，L3 有事实条件；
- 规则 ID 在 92 条清单内且任务至少引用一条实际规则；
- 能力、目标路径、推理、预算、重试和失败策略合法；
- 依赖无环，确定性事实、最终采用和 100% 门禁顺序正确；
- 计划中所有真实调用均标为禁止执行，结果只保存规划证据；
- 新智能体默认4174并记录受控回退端口；旧固定流程4173、旧项目数据和98%状态不被计划引用为新智能体运行值。
- 页面逐项读取项目 `activePlanId` 指向的唯一结构化计划，重新规划保留旧记录；未来执行器无需迁移或重建计划即可消费同一任务ID、依赖、状态和输入引用。
- T01—T20只用于检查 `checkpointCoverage`，用户页面显示由事实驱动的动态任务图；校验失败只能退回具体错误，不得生成固定替代计划。
- `executionEnabled=false` 由程序强制，确定性解析和 `trip_planner` 之外的能力调用统计全部为零。
