# Simple Pipeline 生成链路可靠性改造方案

日期：2026-09-22，更新：2026-09-23
状态：部分实施，已完成一次新项目真实回归；最终追加修复尚待完整回归与独立验收，详见第11—12节。第13节为本次新增、尚未实施的知识库找图链路专项方案。
依据：初始方案基于 `codex/image-retrieval-reliability` 的 `d28e85f`；第13节基于当前 `2d830be`、两轮真实运行诊断及用户要求的搜索链路排查。本文是长期技术方案，不保存客户原始资料、运行日志或凭据。

## 1. 目标与边界

目标是一次完成可控链路缺陷的系统整改：主题有效则进入正确检索，已有合格素材能进入对应位置，事实缺项不会伪装成研究完成或触发旧模板，失败有准确原因，编辑器与实际成品一致。验收按通用行为和完整数据流进行，酒店名和活动名只作为样本。

内容业务规则以 [00 当前规则索引](../../rules/00-当前规则索引.md) 及其 01—06 为准；执行架构沿用 [四类规则归一](simple-skill-pipeline-四类规则归一.md)。本提案不替代这些规则，不引入独立图片审核页、多层 Reviewer、自动第二轮业务搜索、无限模型重试或新的部署服务。

“完成整改”不等于保证互联网永远有所有照片、来源永远可访问、模型永不出错。可验收承诺是：已定义范围内的有效输入不因内部契约误拦；合格可访问素材不因内部处理漏用；外部无证据、访问失败和系统缺陷能够区分；异常有界结束，不伪造事实和成功。

## 2. 已确认的根因

| 层次 | 根因 | 已见症状 | 责任边界 |
|---|---|---|---|
| 业务编排 | 酒店代表图允许在多种真实空间中择优，前置规划却按理想画面中的“或”阻断整个位置；搜索与审核没有完全共用最低视觉目标 | 实体目录可匹配，但从未查询；普通用车因环境选择被挂起 | 明确目标类型，统一 Core 与偏好，先消除规则冲突 |
| 数据契约 | 素材存在、当前位置资格、是否已采用和是否能预览混为候选状态；各消费者另算 | 提示有候选但列表空；其他位置已有相关素材，本位不可发现 | 一份状态来源，多种派生视图 |
| 来源适配 | 普通网页、媒体说明页、缩略图和原图缺少统一类型归一 | HTML 当图片下载，缩略图当原图判尺寸，装饰图片消耗预算 | 适配器输出标准资源描述，再统一技术与视觉校验 |
| 事实研究 | 仅验证已返回条目，不验证请求类别完整性；缺项被解释成没找到 | 设计漏项仍被整体 success 掩盖；图片 URL 冒充文字证据 | 四类终态完整，证据成立与任务结束分别记录 |
| 写回与展示 | 以非空事实数量判断新旧结构；位置和选择状态多处推断 | 新项目回退旧段落；候选存在但客户图片位为空 | 版本化读取与统一投影，稳定绑定 |
| 验证 | 部分测试检查源码形状，甚至固定了错误行为；专项测试入口分散 | 单元测试通过，真实组合仍失败 | 完整链路行为断言与固定回归集合 |
| 外部依赖 | 429、403、404、来源没有资料、模型漏项或非法输出 | 搜索慢、证据不足、审核未完成 | 有界调用、正确降级、可观测结果，不归咎为内容无匹配 |

本轮 Planner JSON 正常，不应把所有缺图继续归因于历史截断问题；但事实研究客户端仍有独立解析路径，应一起纳入协议整合。

## 3. 目标架构与职责

保留现有主链：事实解析 → 单次 Planner → Copy 与 Image 并行 → 确定性采用/写回 → 同一客户数据投影 → 编辑器及 2000px Renderer。

统一五类内部契约，不增加顶层业务阶段：

| 契约 | 提供方 → 消费方 | 必须表达 |
|---|---|---|
| 位置目标 | Planner/确定性版面 → Image、Copy、校验器 | 稳定 slotId、事实引用、目标类型、Core、Prefer、身份与地域边界、必要性、目标指纹 |
| 来源结果 | 知识库/Web 适配器 → 候选处理 | 是否实际查询、范围、无匹配/范围为空/范围歧义/服务失败、资源类型、来源及逐图证据 |
| 素材与资格 | 下载/审核 → 采用与编辑器 | 素材身份、预览和原件、本位资格、完整审核状态、硬拒绝证据、规则指纹 |
| 事实研究 | Research/核验 → Copy、factRows | 每个请求类别的终态、候选来源、通过事实、拒绝或缺失原因、可观察的执行记录 |
| 采用快照 | 采用/写回 → 客户投影、编辑器、Renderer | slotId 到 assetId 的绑定、用户锁定、修订号、必需覆盖与可选移除结果 |

后续实现将契约落在共享 schema/判定函数，并覆盖全部真实消费者；本文字段名是设计表达，不宣称已经存在可调用的新接口。

## 4. 需要明确调整的业务编排

### 4.1 一份结构化视觉目标作为唯一判断依据

建议版本化区分两种目标：

- `entity_representative`：展示指定实体的真实代表空间。酒店身份不可替代，明确保留 `exactIdentityRequired=true` 及逐图身份核验，空间类型按已允许的酒店代表图范围择优；Planner 提供偏好，不必让每句理想描述都成为搜索前置硬条件。
- `specific_scene`：展示确定的主体、必要动作及事实边界。客户文案要求具体房型、专属设施或独特体验时使用该模式，不得借代表图模式弱化证据。

这需要同步澄清现有“一位一明确画面”与酒店代表图候选池规则，属于本提案的职责调整，不能作为当前规则下随意跳过校验的理由。程序不得只按名称含“酒店”来设定模式或身份要求，不得静默改写历史 unresolved 目标。若需要 Planner 新增模式字段，须同时修订当前限制输出字段扩张的正式约定，并更新提示、schema、消费者和旧数据读取；内部契约可以先复用现有 queryCore/exactIdentityRequired/minimumVisualProof，不重复制造同义字段。

普通图片位以结构化 Core 的一致性判定可执行性。环境、光线、构图等确属偏好的替代表达不应仅因含“或”阻断搜索。真实 Core 二选一、与事实冲突、身份不明仍保留问题；不能删除“或”或取第一个词来假装修复。自然同框主体可保留，独立场景不得硬拼。

Planner 单次输出负责语义收敛，程序负责类型、完整性、引用、一致性和已经定义的等价归一。保留现有受限技术补救；不因业务校验失败重新调用整份 Planner。只有已完整、无歧义的独立单元可继续，受损单元不能被制造成成功。

### 4.2 搜索与审核必须复用同一目标

形成目标后冻结指纹。Query 只执行 Core；Scope 约束目录与地域；身份证据独立检查；Prefer 只参与排序。下载、审核、自动采用与换图不能再次从理想画面长句推导更严格条件。

酒店目录通过实体登记、受控别名、完整路径和国家/地区证据确认，不在代码里积累酒店专用替换分支。歧义不得靠扩大模糊匹配解决。目录维护是素材管理数据，检索算法只消费统一映射。

## 5. 检索和资源处理

### 5.1 明确一次业务批次内部的状态流转

- 目标有效 → 优先当前已授权/已获取素材及允许知识库范围 → 当前候选池处理 → 按正式规则决定下一 Query、Scope 或 Web。
- `no_match`、`empty`、目录歧义、服务 unavailable/429/timeout、审核未完成是不同结果；保留现有规则允许的受控接续，不能所有失败都进入扩搜。
- 官网拒绝时在同一批次的允许来源中继续，不反复撞击同一站点，也不把访问失败解释成目标不存在。没有可访问合格来源时有界结束。
- 每次转移记录原因、实际请求数、处理与待处理候选数、停止条件；有合格本位素材却未填充时必须能说明是锁定、去重、原件失败还是其他条件。
- 每个请求和队列有明确技术超时、取消和尝试上限；技术重试与业务接续分别计数，不重置累计搜索/页面/下载/审核额度。

### 5.2 标准化资源，而不是按 URL 尾缀猜类型

适配器统一返回 pageUrl、previewUrl、originalLocator、真实 MIME/媒体类型、原图尺寸（如可得）、稳定来源身份、逐图说明和归属证据。字段未知必须明确，不以预览冒充原件。

- 普通 HTML/gallery、媒体 File 页面、CDN 缩放资源、知识库 preview/matched_file 分别做薄适配，后段复用统一实现。
- Wikimedia 的不同入口都进入媒体元数据解析；不盲目删除路径生成未经验证的“原图”，也不把说明页当图片。
- 先排除可确定的图标、装饰线、文档缩略图等；未知相关性不能伪装为硬错误，仍可按现有预算交视觉判断。
- 尺寸不足先区分“下载的是缩略图”与“已确认原件不足”；存在可信原件定位时取得原件再判定，失败记录与真小图区分。
- 使用同一版式适配函数处理自动采用和最终渲染；宽卡变更重新检查实际放大与裁切，不靠一再降低尺寸门槛。
- 公网下载 SSRF、重定向、解码、体积和 MIME 边界保持；内部知识库仍使用独立受控连接器。

## 6. 素材、资格、分配与界面统一

### 6.1 三层数据分离

- **素材 Asset**：稳定 assetId、来源、内容哈希、预览/原件关联、本地文件可用性、技术检查结果。
- **本位资格 SlotCandidate**：slotId、assetId、targetFingerprint、qualification=`eligible/rejected/unreviewed`、审核完整性、证据、规则/审核版本。
- **采用 Selection**：slotId、assetId、auto/manual/upload、locked、revision；未选中和被其他位置使用不改变内容资格。

同图可有多个位置关联，但不能把 A 位的审核通过直接当作 B 位通过。全局硬错误始终禁止；本位拒绝也不能通过换 candidateId 被绕过。

### 6.2 一个决策入口服务自动采用、换图和提示

服务端集中计算 `canPreview/canConfirm/canAutoAdopt/blockedReason` 及对应数量，前端不再根据候选总记录数另行推断。提示“有可确认图片”必须真的存在当前界面可预览、规则允许确认的候选。

自动采用同时要求本位完整审核、eligible、原件本地可解码、版式适配、去重通过、无用户锁冲突。审核超时、字段不全、下载失败都不得变成通过。

### 6.3 项目级候选发现与确定性分配

已获取素材可根据结构化主体/身份关联到其他相关位置，复用文件和真实证据。只有目标及审核指纹完全兼容才复用资格，否则在当前业务批次既有审核额度内完成本位判断；批次结束后不自动另开补审/补搜轮。

自动分配以用户锁定为先，保障必需覆盖，再按角色适配与质量择优；同一素材和近重复簇不得重复占位。使用稳定决策顺序和集中去重登记，不能由并发请求的先后到达决定抢占。已有多候选时可做确定性重分配，不修改 Core、不牺牲必需位给装饰位补图。

人工选择已用图遵守现有移动语义，必须同时更新原位、目标位、锁定和覆盖状态。保存失败保留原有有效快照；自动任务不得覆盖之后发生的人工决定。

## 7. 酒店事实研究与结构化展示

每次请求的四类都必须返回结果，但不要求每类都有事实。设计包括建筑风格、材料、布局与设计理念，不强制设计师姓名。

内部原因至少区分：未执行、输出漏项、未取得证据、来源访问失败、证据不合格、核验预算耗尽、成功。模型自报“已查过”与程序可观察的查询记录分开；没有逐类查询轨迹时不能宣称实际穷尽搜索。

主研究请求中为每类准备现有规则允许的候选来源及备选页面，逐页保留真实摘录，合并重复 URL，一页证据可支持多个字段。官方优先；受控外部页面继续遵守数量和字段限制，优先覆盖仍缺字段。没有候选的类别不得由程序凭空补事实。

**建议同时调整酒店事实的“一次研究”编排限制**：主请求后仍缺类别或现有来源不可核验，且存在新的允许来源方向时，最多合并发起一次仅针对缺失类别的补证。它是明确计数的业务调用，不伪装成 JSON 技术重试；不重新研究成功字段，不重新规划行程，不重跑整份文案。两次合计共享酒店研究的来源范围、外部页面上限及有界执行额度；无新方向、预算不足、重复失败或第二次仍缺失即停止。仅支持公开酒店属性，不扩展到订单承诺或其他时效政策研究。

该建议需要同步修订03的单次研究约定，未实施前继续遵守当前规则。如果维持绝对单次请求，系统能准确识别漏项，却不能可靠补回模型未提供的事实；仅改状态提示不足以满足减少人工补资料的目标。即使允许一次补证，也不承诺所有酒店永远四项齐全。

补证次数按当前运行的同一酒店实体持久记录，所有 Copy 目标共享；接口重入、并发消费者或进程重启不得重置，补证自身不递归。业务调用和底层技术补救分别计数并共享明确物理请求上限。身份冲突、全局鉴权故障、取消、截止时间已到均不自动补证。此调整可能增加部分项目的耗时与调用成本，应在真实回归中单独统计其新增调用和补齐收益。

JSON协议使用共享实现：检查终止原因、语法、schema、类别覆盖；格式修复不补事实、不把截断文本当完整结果。合法 JSON 但漏类别属于内容合同不完整，不可借“技术重试”额外发起业务研究；只能按上面明确建议的有界补证策略处理。事实研究、Planner、视觉审核共用协议诊断，但各自合法的重试次数与业务策略不混同。

证据核验区分图片与网页、实际页面身份、品牌新闻稿关联、原文片段及数字/单位，不能只认域名相似或几个散落共有词。正文来源失败不影响已验证字段，也不得从图片推断设计、设施或已订房型。

新结构与旧结构通过版本和字段是否存在判断。新项目四类全空仍是新结构，只隐藏空行；真正缺少结构字段的旧项目才兼容旧段落。编辑器、客户投影、预览和导出共用同一表达函数。

## 8. 运行与渲染闭环

生成前验证实际渲染服务可用、字体资源及保存能力，记录代码、契约、提示词和规则指纹。Renderer 使用受控且真实可用的运行入口，不能等到所有搜索结束才发现连错端口；不据此改变模型或外部服务配置。

稳定 slotId/实体 ID 决定归属，数组下标只作投影。采用快照与客户数据使用同一 revision；保存成功再对外报告采用，渲染成功才报告该 revision 有可下载成品。新编辑使旧成品过期，但不删除用户已有文件。

必需缺图进入可编辑草稿；可选图片位移除重排，不删除业务文字。状态提示不能把这些情况合并为全部成功；正式成品仍按当前必要性、客户信息隔离与实际 2000px 检查执行。

耗时记录区分排队、网络、解码、审核、渲染墙钟及累计操作时间；并行耗时不可相加冒充总时间。优化集中在同批缓存、重复请求、无效候选及限流控制，不靠增加并发和无上限重试。

## 9. 实施顺序与兼容

1. 固定当前代码/规则版本，建立通用失败分类、机器契约和回归矩阵；把已确认错误样本提炼为脱敏、可维护的测试输入，禁止把客户原文或凭据提交到仓库。
2. 同步落实第4节的职责约定与 Planner/Image 共用目标；统一结构化响应和事实类别覆盖。现有旧项目通过读取适配器兼容，不批量改写。
3. 统一来源资源、候选资格、同批状态流转与分配；所有入口切换到同一判断函数，移除重复判定后再做清理，避免两套状态长期并存。
4. 接通稳定绑定、写回快照、编辑器/客户渲染与新旧事实结构，补上启动与导出检查。
5. 完成固定回归集合和新项目真实回归后一次交付，明确剩余外部依赖和未验证项；不把每个模块补丁分别要求用户跑整份 Excel。

以上是同一改造的依赖顺序，不创建新的产品功能、服务或长期双流程。新任务写新契约，历史数据只读适配；历史锁定图与人工内容保持。缺少新字段不能批量清空旧图，也不能反过来给旧记录授予未证明的跨位自动采用资格。回退代码时不得破坏已经保存的新项目，旧版无法读新契约的情况必须在发布前验证。

涉及正式规则修订的目标模式、跨位自动分配及酒店事实有限补证，应在实施同一变更中明确写回 03/04 和程序落实对照表。本提案不直接修改正式规则，也不假定用户已批准新的运行策略。

## 10. 封闭回归与验收标准

### 10.1 验证方式

- 单元测试验证边界；集成测试必须让同一素材/事实经过真实归一、判定、写回和展示，不能只用源码正则或伪造最终 success。
- 建立一个明确的本次链路测试入口，包含 Planner 契约、Research、知识库、网页/媒体、审核、手动操作、写回、客户投影和渲染；保留已有受影响检查及 build/test:sites。
- 使用录制后脱敏的响应或等价固定素材验证可重放行为；替换实体名、同义表达、语言、返回顺序与并发顺序，防止样本专用逻辑。
- 注入限流、超时、截断、非法 JSON、HTML 冒充图片、原件失效和保存失败，验证准确终态及锁定不丢失。
- 全部通过后使用新项目与新浏览器数据做真实回归，覆盖游猎、多酒店/多交通以及自费/待确认场景；至少保留未参与开发调试的真实样本。旧运行只能诊断或兼容验证，不能作为新实现验收。

### 10.2 必须通过的矩阵

### 10.3 完成条件

1. 上述矩阵全部具备行为断言并通过，受影响旧能力无未解释回退；测试数量不作为质量结论。
2. 受控验收素材中，已知有合格、可访问、满足本位条件且无锁定/去重冲突的图片全部自动填入对应位置；任何未填位都有可以验证的终态。
3. 不存在“未发起搜索却显示没找到”“无可用预览却显示可确认”“已采用却未写回/渲染”“漏研究类别却记查无证据”等状态错误。
4. 新项目不因事实为空回退旧结构，历史项目不丢内容；订单事实、费用、身份和内部信息边界保持。
5. 同一版本完成新项目真实回归和实际2000px核对；记录必需位覆盖率、误配、人工介入、每类失败及端到端耗时，排除不了的缺图不得一概归为外部原因。
6. 无隐藏业务调用：Planner单次、Image单轮；若采用酒店事实有限补证提案，额外业务请求最多一次且单独记录。无无界重试、无重复放置和越过用户锁。性能用同一版本/同等输入比较，既有20分钟标准项目目标不能靠降低质量达成；不承诺未经实测的新数值。
7. 提交实现、契约、测试及真实证据，按项目约定待独立复核。方案完成、实现完成和验收通过分别标记。

### 13.2 修改范围与依赖顺序

1. **固定图片位与修复可证明的规划表达。** Parser/版面先形成带稳定 `sourceKey/slotId`、必需性的候选位置；Planner 从既定候选中明确选择保留可选位置，并为每个保留位置确定唯一 `visual`、Core、身份、地点角色和 Query。输出后比较位置集合，记录必需位缺失、保留位缺规划、重复、可选位被明确省略及无来源位置；不能用 Adapter 为缺失位置编造画面。酒店主图已由事实锁定具体酒店、没有专属房型/设施/必要动作时，允许将“城市酒店外观或大堂”这类同店普通代表空间归入现有酒店代表图类别池。普通交通图只有 Core 和原 Query 已确定唯一车辆主体与动作时，才能把道路或机场等非核心背景选择归入 Prefer。停靠或飞行、不同交通工具、专属设施、不同活动主体、缺少 Core 或彼此冲突的 Query 仍为 `unresolved`。任何局部修复须保留原值、依据、结果和错误码；不增加 Planner 调用，不自动启动第二轮图片业务搜索。涉及 `agent-trip-planner.mjs`、`simple-plan-adapter.mjs` 和对应合同测试。
2. **恢复目录树读取，但不绕过实时身份校验。** 在 `knowledge-scope-resolver.mjs` 区分超时、网络/服务失败、无效层级、取消和目录本身不存在。一个图片批次共享成功或正在进行的层级请求；失败的 Promise 不得永久复用。瞬时技术故障最多作一次有界重试；单次请求截止须短于现有目录请求总截止时间，剩余预算不足则不重试；取消、确定的客户端错误和无效响应不盲目重试。若最终失败，逐位记 `hierarchy_unavailable` 并按正式规则进入安全 Web 降级，不记作“知识库查无图片”。历史 `knowledge-node-mappings.json` 仅在实时层级中验证节点，不能独立充当当前目录或跳过身份检查。技术重试计数与业务搜索轮次分开。
3. **在服务恢复后验证目录、范围和索引。** 用 Planner 的酒店正式名、受控别名、地区/国家与实时层级唯一确认酒店根目录；同名酒店、错地区、多个等分目录保持歧义，禁止模糊选第一个。酒店普通代表图依 `IMG-008` 在合适 `Stay` 子目录和酒店根目录内按外观、套房、泳池、公共空间顺序查询并早停；来源路径和逐图身份仍须复核。交通范围按 04 正式规则核对地区→国家→根知识库的实际实现，不能把地点误写成普通 Query，也不能越国检索；DAY/体验按具体地点与允许的上级范围处理。对 JW 与丽思建立只读对账：共享源文件清单 → 实时目录节点及 ID → 带该节点范围的图片查询 → 返回 `source_paths`/原件。若知识库提供只读索引清单或管理方导出，再核对索引资产记录；否则用精确文件名抽样查询并明确保留索引覆盖未证实。若确认索引缺文件，单列素材入库与授权任务，不通过放宽检索或直接扫描共享盘假装修复。
4. **保留同批次受控接续和资格门槛。** 知识库服务失败、目录未定位、已查询为空、预览已返回但原件失败、来源路径冲突及视觉未完成分别记录。只有正式规则允许的终态才从当前知识库阶段接续 Web；Planner 目标未确定、身份未知或视觉审核异常不能靠泛词扩搜掩盖。Web Query 继续由冻结的 Core 和必要身份形成，检查页面访问与下载预算是否给后备表达留机会；已获取候选按实际主体、酒店身份、交通类别、尺寸和本位资格判断。原图本地保存、完整终审、去重和版式适配全通过才自动采用，不把“找到候选”当“已采用”。涉及 `simple-image-skill.mjs`、`knowledge-image-search.mjs`、`image-web-execution.mjs` 与候选/采用测试。
5. **一张图一个可追溯漏斗。** 复用现有内部 `pipelineEvidence` 和 `metrics`，逐位记录 Planner `ready/locally_repaired/unresolved`、层级请求与失败类型、根目录候选和确认结论、选定 Scope 节点、实际 Query/查询 ID、返回与路径拒绝数量、preview/原图/尺寸/视觉结果、Web 进入原因及最终采用/停止原因。批次统计区分“规划跳过”“目录不可用”“目录未匹配”“查询为空”“候选不合格”；`knowledgeActualRequests=0` 时必须可复算是哪一关阻断。这些诊断只进服务端运行记录与现有内部审计数据（按既有权限保护），不进入客户 JSON/预览/PNG，也不记录凭据或内部服务地址。

当前已确认的规则落差是 `buildKnowledgeScopePlan` 对交通只建立国家 Scope，而正式图片规则要求地区→国家→根知识库逐级接续；实施第3项时应补齐该链路，并在放宽到根范围时逐图核对国家与交通类别，不能因范围扩大误配；根范围必须使用实时层级明确解析的节点 ID，禁止用空 Scope 代替，返回图须证明目标国家与交通类别。Web 回退也应使用固定 Core 回放两轮不同搜索结果，定位是查询表达、来源页召回、页面访问、下载还是视觉硬拒绝造成之前可用图片未再出现；不得仅提高候选评分权重。

### 13.3 验证与交付门槛

- **固定回放：** 把 10:06/10:39 已确认的失败形态做成脱敏、可维护的 Planner/Scope/候选样本。正例覆盖普通酒店代表空间和已证明只是背景的交通 A/B；反例覆盖不同必要动作、专属房型/设施、必需位缺失或已保留位缺画面、错酒店同名目录和无安全 Query。正例必须进入搜索，反例必须保持未解决且不得自动采用。历史运行只用于复现，不计作新实现验收。
