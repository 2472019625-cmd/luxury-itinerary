# 智能体项目服务端存储：本地落地说明

本轮只改智能体试验区的代码与本地环境；正式云服务器、线上数据库和历史项目均未直接修改。

## 当前数据边界

- 业务项目目录：`app/workspace/agent-v1/catalog/projects.sqlite`（SQLite WAL）；按登录账号的服务端用户 ID 隔离，并使用修订号阻止多页面静默覆盖。
- 原始 Excel：`app/workspace/agent-v1/sources/<业务项目ID>/original.xlsx`。
- 制作批次、图片及长图：仍位于现有智能体和 Simple Pipeline 的服务端项目/输出目录，由业务项目记录当前批次与历史批次 ID。
- 浏览器旧项目仅提供显式导入入口；新项目不再以浏览器存储为权威数据。导入后应核对原始 Excel，因为旧浏览器记录可能没有原文件二进制。
- 点击“新建行程”只打开输入页；当前界面的首次有效输入是上传 Excel。服务端创建成功后才出现项目卡。服务端保存失败时显示错误，不自动退回浏览器旧数据。

## 回收站与恢复

移入回收站先停止当前及历史关联的运行任务，再记录删除时间和30天到期时间。恢复仅恢复业务项目与已保存资料；已停止的制作批次不能续跑。后台每小时检查到期项目，服务启动时也检查一次；清理失败保留记录供下次重试。手动永久删除同样清理关联制作目录、专属资料和成品。

## 本地验证

在 `app/` 运行 `npm run build`、`npm run test:agent-storage`、`npm run test:agent-planner`、`npm run test:simple-pipeline`、`npm run test:sites`。存储测试覆盖账号隔离、重启后持久化、并发修订冲突、停止运行、恢复、手动删除及到期清理。

## 正式云部署前仍需完成

当前 SQLite 方案适合单台持久磁盘的本地/单实例验证，不等于多实例云存储方案。正式上线须先确认 Node 运行版本、持久卷与备份恢复、对象文件存储、任务执行与数据目录的一致性，并做账号迁移和真实多用户回归。当前 Node `node:sqlite` 仍会给出实验特性提示；若计划多实例或跨机器扩容，项目目录应迁移至托管数据库，原始文件及成品应迁移至对象存储。不可直接把当前本地数据库文件复制覆盖正式环境。
