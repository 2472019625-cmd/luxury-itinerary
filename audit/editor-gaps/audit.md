# 编辑能力缺口审查

日期：2026-08-27

## 审查范围

编辑预览页中的模块选择、具体内容点击、文案字段绑定、多图片选择、图片替换与裁切焦点。

## 用户目标

定制师应能从左侧模块或中央预览进入准确的内容对象，在右侧修改该对象的全部业务文案和对应图片，并即时看到预览变化。

## 步骤与状态

1. 每日行程图片编辑：部分可用。右栏只绑定当天第一个景点的第一张图片。
   - 证据：`01-day-image-single-selection.png`
2. 行程总览文案编辑：不可用。右栏只有说明占位，没有真实字段。
   - 证据：`02-overview-no-fields.png`
3. 特色餐饮模块选择：不可用。文案页没有模块标题、引导文案或餐饮卡片字段。
   - 证据：`03-dining-image-no-item-picker.png`
4. 特色餐饮图片编辑：不可用。没有当前图片预览或图片列表；点击预览内具体餐饮图片后，右栏状态不变。
   - 证据：`04-dining-image-editor-empty.png`

## 根因

- 当前选择状态只记录模块或天数：`{ type, index, module }`，没有记录卡片索引、景点索引和图片索引。
- 预览点击只识别外层模块 `.overview/.dining-section/...` 或整天 `.day-section`，不能识别具体行程总览卡片、酒店卡片、餐饮卡片、交通卡片、景点卡片和单张图片。
- 文案表单仅实现每日主题/每日描述、封面标题/副标题、总价/报价说明；其他模块统一落入说明占位。
- 图片读写仅实现封面图和 `days[dayIndex].spots[0]`，因此每日行程永远显示第一个景点图片；酒店、餐饮和交通虽然显示“图片”标签，但没有实际数据绑定。
- 裁切只写入 `${x}% 50%`，纵轴固定为 50%；封面、酒店、餐饮和交通也没有对应焦点写入逻辑。
- 预订流程由组件硬编码，不在项目数据中；“预订与安全”隐藏开关只隐藏安全区，不能隐藏预订流程本身。

## 建议修改

1. 建立统一选中路径：`{ module, itemIndex, subItemIndex, imageIndex }`。
2. 给可编辑预览节点添加稳定的数据路径，例如 `data-edit-path="days.2.spots.1"`，点击后直接定位真实数据，不再依赖外层 CSS 类猜测。
3. 为各模块建立字段配置表，由同一套通用表单生成右侧编辑器：
   - 产品亮点：每条标题与描述。
   - 行程总览：每一天的路线节点、主题、总览备注，并直接回写同一天数据。
   - 酒店：地区、晚数、短名、正式名称、介绍、卖点和每张图片。
   - 餐饮：模块标题/引导文案，以及每个餐饮项目的位置、名称、英文名、介绍和图片。
   - 交通：类别、服务等级、使用区间、车型/座位数、介绍、特色和图片。
   - 每日行程：日期、主题、路线、节奏、用餐、酒店、正文、贴士；每个景点的名称、介绍、状态、提醒和图片。
   - 费用：总价、单位、报价说明、包含、不含、退改政策。
   - 注意事项：每组标题与条目。
4. 图片页先显示“本模块全部图片缩略图”，按卡片分组；选中缩略图后再显示重新搜索、本地上传、删除/恢复和裁切。
5. 把裁切焦点改为二维焦点：可在预览图上拖动焦点，同时提供横向 X、纵向 Y 两个滑杆与“居中”按钮；数据统一保存为 `focus: "x% y%"`。
6. 对无图片模块隐藏“图片”标签；对有图片但当前没有图片的对象显示明确的“添加图片”空状态。
7. 预览点击和右栏列表双向同步：点中央图片会选中对应缩略图，点缩略图会把中央预览滚动到对应卡片并加选中边框。

## 优先级

- P0：补齐数据路径选择和真实读写层，否则后续字段和图片功能都会继续错绑。
- P1：补齐所有业务模块文案字段、图片缩略图选择、精确图片替换。
- P1：二维裁切焦点与即时预览。
- P2：空状态、选中态、滚动定位、键盘焦点与撤销反馈。
