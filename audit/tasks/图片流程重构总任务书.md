## 一、项目与执行边界

项目目录：

`D:\奢游\行程单报价单\奢游行程单美化-本地版`

执行前必须重新读取：

- `audit/PROJECT_HANDOFF.md`
- 项目内适用的 `AGENTS.md`
- `audit/审查问题台账.md`
- `rules/图片使用规范.md`
- `rules/IMAGE_SEARCH_RULES.md`
- `app/prompts/image-blueprint-planner.md`

当前目录不是 Git 仓库，不能依赖 `git status`、`git diff` 或 Git 回滚。实施前必须制作带时间戳的项目备份，并在交接中写明备份位置。

不得覆盖现有修改，不得把旧项目或演示数据当成当前实现，不得修改或输出任何密钥。

本批只允许修改：

- 图片蓝图；
- 图片搜索；
- 图片自动筛选；
- 图片与版面的绑定；
- 编辑器换图和本地上传；
- 单图片位重搜；
- 图片来源账本；
- 成品图片复查；
- 与上述流程直接相关的进度展示。

本批不得改变：

- Excel 导入与确定性事实解析；
- 日期、人数和天数；
- 路线、酒店、晚数、餐食和交通事实；
- 费用、包含、不含和退改数据；
- 客户文案编辑能力；
- 项目保存与恢复；
- 2000px PNG 导出；
- 现有品牌视觉、版式和模块顺序；
- 模型密钥、计费配置和主文案模型用途。

用户手工选择、移动或上传并确认的图片属于用户决定，任何后续自动流程都不得覆盖。

## 二、目标体验

目标不是增加一个新的图片管理后台，而是让用户获得以下体验：

1. 上传真实行程文件；
2. 程序准确解析事实；
3. GLM-5.3-Flash 理解整趟旅行并生成视觉蓝图；
4. 系统按照蓝图自动搜索和放置图片；
5. 自动流程完成后直接进入编辑器；
6. 用户在编辑器中通过一个简单弹窗换图、跨模块移动图片、搜索更多或本地上传；
7. 系统基于实际长图进行一次图片复查，只处理失败位置；
8. 用户无需进入独立图片审核页面，也无需逐张确认“自动通过”图片。

后台仍然保留图片真实性、技术质量、来源和重复检查，但不把审核工作转嫁给用户。

## 三、完整目标流程

```text
上传文件
→ 确定性解析行程事实
→ 建立真实版面图片位
→ GLM-5.3-Flash 理解整份行程
→ 输出结构化视觉蓝图
→ 程序校验蓝图
→ 按固定 slotId 搜索图片
→ 自动检查和选择图片
→ 按固定 slotId 放入版面
→ 直接进入编辑器
→ 基于实际 2000px 版面进行图片复查
→ 只重新处理复查失败的图片位
→ 用户编辑、换图、上传与导出
```

## 四、新增视觉蓝图策划阶段

### 4.1 模型与职责

视觉策划模型使用：

`GLM-5.3-Flash`

系统提示词使用：

`app/prompts/image-blueprint-planner.md`

视觉模型只负责：

- 理解整份行程；
- 判断旅行定位和核心价值；
- 建立整趟旅行的视觉故事；
- 理解每天的完整内容和视觉角色；
- 为真实版面图片位生成结构化蓝图。

视觉模型不负责：

- 直接读取和猜测原始表格结构；
- 修改任何行程事实；
- 实际搜索图片；
- 编造图片 URL；
- 决定费用、日期、酒店、餐食或交通内容；
- 输出面向用户的长篇分析过程。

### 4.2 输入结构

程序必须先完成确定性解析，再构造视觉模型输入。至少包括：

#### `itineraryFacts`

本次上传文件中已经解析和校验的完整事实，包括：

- 日期和天数；
- 人数；
- 路线；
- 每日完整描述；
- 每日主题；
- 景点和活动；
- 交通和预计时间；
- 餐食；
- 酒店和晚数；
- 活动强度；
- 包含、不含、自费、可选和待确认状态；
- 返程和过夜类型。

#### `layoutSlots`

当前模板真实存在的图片位。每个图片位至少包含：

- `slotId`
- `module`
- `fieldPath`
- `dayIndex`
- `adjacentText`
- `ratio`
- `maxImages`
- 当前版面用途
- 是否允许留空

#### `lockedImages`

用户已经手工选择、移动或上传并锁定的图片以及当前位置。

#### `projectPurpose`

固定说明输出用于“奢游国际 2000px 客户行程长图”，不是小红书、朋友圈、公众号或其他渠道。

### 4.3 蓝图输出与绑定

蓝图必须遵循提示词中的 JSON 格式。

每个图片位通过程序生成的稳定 `slotId` 绑定。后续搜索、候选记录、自动选择、人工换图、单槽重搜和最终复查全部使用同一个 `slotId`。

禁止继续通过以下方式猜测图片位置：

- 标题文字相似度；
- 地点名称相似度；
- 搜索词模糊匹配；
- 网络请求完成顺序；
- 数组位置碰巧一致。

双图位置必须拆成两个有明确职责的子图片位，或者在蓝图中为两张图分别定义角色，不能按分数直接取两张相似图片。

### 4.4 蓝图程序校验

模型返回后必须进行程序校验：

- 返回结果是合法 JSON；
- 只能返回输入中存在的 `slotId`；
- `slotId` 不能重复；
- `sourceEvidence` 能在输入事实中找到；
- 自费、可选和未确认项目可以成为主视觉；程序必须验证其状态在相邻正文或安静状态行中明确展示，并与费用不含或待确认信息一致，不能暗示已经包含或已经确认；
- `mustHave` 不能包含输入中不存在的事实；
- 图片数量不能超过图片位允许数量；
- 用户锁定图片不能被重新规划；
- 不能包含虚构图片 URL；
- 同一天和整份行程不存在明显重复主题；
- 返程日不能规划“入住飞机”类图片或住宿画面。

第一次校验失败时，可以把明确错误反馈给模型并请求修正一次。

第二次仍失败时，不得回退到当前按地点或标题简单搜图的旧逻辑。直接进入编辑器，受影响图片位留空，并允许用户重新规划、搜索或上传。

### 4.5 蓝图保存和缓存

视觉蓝图必须保存到当前项目，并记录：

- 蓝图版本；
- 模型名称；
- 生成时间；
- 提示词版本；
- 输入事实指纹；
- 版面图片位指纹。

只有以下内容变化时才重新规划整份蓝图：

- 行程事实发生实质变化；
- 模板图片位发生变化；
- 提示词版本发生变化；
- 用户主动要求重新规划整份图片故事。

单图片位换图、上传或重搜不能重新生成整份蓝图。

## 五、每日内容理解与整份图片故事

每日图片规划必须读取当天完整内容，不得只使用景点名称、城市、路线节点或标题。

至少需要理解：

- 当天主题；
- 完整行程描述；
- 前后发生顺序；
- 交通方式和移动时间；
- 餐食；
- 住宿；
- 活动强度；
- 具体活动；
- 项目是否已确认、包含、自费或可选；
- 当天在整趟旅程中的视觉作用。

模型必须先规划整趟旅程的视觉节奏，再决定每天图片：

- 启程：建立目的地第一印象；
- 探索：展示地貌、文化或生态进入感；
- 沉浸：展示私密、松弛和生活方式；
- 高潮：展示最稀缺或最具冲击力的体验；
- 收官：展示从容告别、城市过渡或返程氛围。

不能让多天重复使用同类动物、相似草原、相似酒店卧室或相同摄影角度。

例如：

“抵达内罗毕 → 专车接机 → 前往安博塞利 → 入住雪山景观营地”

应规划目的地初见、乞力马扎罗山与安博塞利环境或真实营地关系画面，不能因为文案出现晚餐就用烛光晚餐作为当天主图。

## 六、取消面向用户的图片审核页面

生成完成后直接进入编辑器，不再要求用户在独立页面逐张处理：

- 自动通过；
- 待确认；
- 人工采用；
- 人工拒绝。

后台仍保留候选状态、来源、评分、判断理由和处理阶段。

后台处理规则：

- 合格图片自动放入版面；
- 明显水印、破图、严重低质、明确错地点、错酒店、错主体和 Logo 代替真实场景的图片自动淘汰；
- 淘汰后在预算范围内自动继续搜索；
- 搜索结束仍没有合格图片时，对应位置留空；
- 缺图不能阻止进入编辑器；
- 不得因为还有待确认图片而停在 97%；
- 自动流程完成并进入编辑器时，进度才可以到 100%。

“取消审核页面”不等于删除安全检查。硬性错误仍不能进入客户成品。

## 七、编辑器换图弹窗

点击任何现有图片或空图片位的“换图”后，打开一个简单弹窗。

弹窗只保留三个主要入口：

1. 适合当前位置；
2. 全部行程图片；
3. 本地上传。

### 7.1 适合当前位置

按照当前 `slotId` 的完整蓝图排序，优先展示与相邻文案、模块职责、图片比例和裁切要求匹配的可用图片。

### 7.2 全部行程图片

展示本次行程搜到并通过基本安全检查的全部可用图片。

不限制用户只能选择原模块的图片。封面、酒店、餐饮、交通和每日行程图片可以跨模块移动。

每张图片只显示必要信息：

- 缩略图；
- 简短来源；
- 当前使用位置；
- 是否由用户上传。

不在主界面展示复杂模型评分和三态审核术语。

### 7.3 跨模块移动与重复控制

选择一张已经使用的图片时，必须显示它当前所在位置。

默认行为是把图片移动到新位置，原位置留空，不能静默复制出第二份。

全份客户长图不得出现同一文件、相同来源图片或高度相似视觉的重复使用。

### 7.4 本地上传

用户可以为当前图片位上传本地图片。

上传后必须：

- 显示真实预览；
- 保存到项目；
- 标记为用户图片；
- 锁定该图片位；
- 刷新页面或重新打开项目后继续存在；
- 后续自动搜索、重新规划和版面复查不得覆盖。

需要继续关注浏览器存储上限，不能把大量高清 Data URL 无限制塞入 `localStorage`。如本批需要改变存储方式，必须先说明迁移和兼容方案，不得静默破坏旧项目。

### 7.5 搜索更多

弹窗提供“为当前位置搜索更多”。

该操作必须：

- 只使用当前图片位蓝图；
- 只重搜当前 `slotId`；
- 只更新当前图片位的候选、来源和失败记录；
- 不修改其他图片位；
- 不覆盖任何人工决定；
- `mustHave` 或 `forbid` 变化时使旧审核缓存失效。

## 八、搜图与自动选图

系统按照蓝图中每个图片位的 `mustHave`、`prefer`、`forbid`、`searchQueries`、`sourcePriority` 和 `fallbackPlan` 搜图。

必须遵守：

- `mustHave` 只包含事实正确所必需的条件；
- `prefer` 只用于排序，不能作为硬拒绝；
- `forbid` 用于淘汰明确错误图片；
- `visualGoal` 不能自动变成 `mustHave`；
- 蓝图中的来源优先级必须真实影响搜索顺序；
- 不能用其他酒店冒充指定酒店；
- 不能用普通风景代替具体活动；
- 不能用 Logo、门头、媒体截图或普通游客照片代替真实高端场景；
- 找不到合格图片时宁可留空。

候选图片必须保留稳定 ID，并与以下信息一一对应：

- 本地预览文件；
- 所属 `slotId`；
- 来源页面；
- 原图地址；
- 来源类型；
- 搜索词；
- 技术检查；
- 视觉判断；
- 最终状态；
- 未采用原因。

所有自动采用图片必须是已经下载并保存的本地文件，客户成品不得直接引用不稳定远程 URL。

## 九、放入版面后的最终图片复查

所有图片放入版面后，必须基于实际编辑器或实际 2000px 成品进行一次全局图片复查。

复查至少包括：

- 图片是否放错模块；
- 图片是否与相邻文案匹配；
- 是否使用错误地点、酒店、主体或交通工具；
- 同一图片或相似图片是否重复；
- 裁切后主体是否完整可见；
- 封面是否代表整趟旅程；
- 双图是否表达不同内容；
- 图片顺序是否形成连贯故事；
- 色调和品质是否明显冲突；
- 是否出现大面积空白、图片过小或版面失衡；
- 2000px 成品中的复合图片是否仍能识别每个主体。

最终复查只能重新处理失败图片位，并限制重试次数。不得重新生成或覆盖整份行程。

用户锁定图片可以显示非阻塞提醒，但不得被后台自动更换。

## 十、真实进度展示

进度必须来自真实阶段，不得直接跳到展示结果。

建议阶段：

1. 读取并解析文件；
2. 校验行程事实；
3. 理解整份行程；
4. 生成图片蓝图；
5. 搜索来源页面；
6. 下载和检查候选图片；
7. 自动选择与放置；
8. 复查实际版面；
9. 保存项目并进入编辑器。

界面应显示当前动作、已完成数量、候选数量、采用数量、缺图数量和当前耗时。

自动流程未结束前不能显示 100%。如果规划或搜图失败但已经按照降级规则进入编辑器，完成状态可以显示 100%，同时明确标记缺图数量。

## 十一、失败与降级策略

### 视觉蓝图失败

- 校验失败后最多自动修正一次；
- 第二次失败后进入编辑器；
- 受影响图片位留空；
- 不回退到旧的地点关键词搜图；
- 提供重新规划、当前位搜索和本地上传。

### 图片搜索失败

- 按蓝图中的 `fallbackPlan` 重试；
- 可以放宽 `prefer`；
- 不能放宽地点、品牌和主体等事实硬门槛；
- 最终失败时留空。

### 最终版面复查失败

- 只处理失败 `slotId`；
- 不覆盖用户锁定图片；
- 不重新生成客户文案；
- 不重新生成整份蓝图，除非确认蓝图本身错误且用户主动同意。

## 十二、非图片功能保护与回归

实施前后应对非图片业务数据生成稳定摘要或哈希，确认图片流程没有改变：

- 标题、副标题；
- 日期、天数、人数；
- 每日主题和路线；
- 酒店、晚数和夜宿类型；
- 餐食；
- 交通；
- 费用、包含和不含；
- 注意事项；
- 定制师信息；
- 项目可见模块；
- 导出尺寸和品牌页。

必须使用新建真实项目测试，不能只跑旧演示数据。

旧项目必须保持可读。任何数据结构升级都必须提供兼容读取或迁移，不能让旧项目白屏、丢失文案或无法导出。

## 十三、最低验收场景

至少使用一份真实肯尼亚行程完成全流程测试，并补充一份结构明显不同的真实行程进行回归。

必须证明：

1. 生成后不进入独立图片审核页，直接进入编辑器；
2. 视觉蓝图来自整份行程，不是逐日关键词堆砌；
3. 第一天图片依据当天完整描述选择，不只是地点名称；
4. 封面不会使用普通酒店卧室代替目的地代表画面；
5. 错误地点、酒店、主体、Logo、水印和破图不会自动进入客户版；
6. 缺图不会阻止进入编辑器；
7. 进度真实显示 1 至 100，并说明正在做什么；
8. 换图弹窗包含“适合当前位置、全部行程图片、本地上传”；
9. 图片可以跨模块移动，但不会产生重复；
10. 已使用图片显示当前所在位置；
11. 单图片位重搜只影响目标位置；
12. 人工选图和上传图片刷新后仍然保留；
13. 人工图片不会被自动重搜或最终复查覆盖；
14. 双图模块两张图片表达不同内容；
15. 实际 2000px 成品完成一次全局图片复查；
16. 导出中不包含审核评分、状态或内部来源账本等内部信息；
17. 日期、人数、酒店晚数、餐食、交通、费用、编辑、保存和导出没有发生非预期变化。

新增或补充测试至少覆盖：

- 蓝图 JSON 校验；
- 非法或重复 `slotId`；
- 自费、可选和未确认项目可以进入主视觉；测试必须验证状态标注和费用边界同步，而不是按未包含状态直接拒绝；
- 蓝图缓存命中和失效；
- 用户锁定图片不被覆盖；
- 跨模块移动不产生重复；
- 单槽重搜只更新目标槽；
- `mustHave` 和 `forbid` 变化使审核缓存失效；
- 视觉规划失败时留空进入编辑器；
- 旧项目兼容读取；
- 非图片业务事实未发生变化；
- 2000px 导出不包含内部审核元数据。

自动化测试不能代替真实浏览器回归。

## 十五、执行完成后的交付证据

执行窗口完成后不能只回复“已经修复”。必须提交：

- 修改文件清单；
- 修改前备份位置；
- 真实完整任务编号；
- 使用的模型和提示词版本；
- 实际生成的视觉蓝图；
- 每个图片位的稳定 `slotId`；
- 搜索到的候选数量；
- 自动采用图片及采用位置；
- 淘汰图片及事实化原因；
- 缺图位置；
- 换图弹窗截图；
- 跨模块移动图片的截图或录像证据；
- 本地上传与刷新恢复证据；
- 单图片位重搜前后对比；
- 进度阶段截图；
- 最终编辑器截图；
- 2000px 导出截图和文件；
- 非图片功能回归结果；
- 自动化测试结果；
- 已知未完成边界。

完成后交回独立审查窗口复核。执行窗口不得自行把 `audit/审查问题台账.md` 中对应问题改为“已关闭”。

## 十六、审查通过标准

独立审查需要使用全新真实项目重新运行，不直接采信执行窗口结论。

只有同时满足以下条件才可关闭问题：

- 蓝图确实来自完整行程内容；
- 搜图确实按固定 `slotId` 执行；
- 图片位置与版面职责正确；
- 无强制人工审核页；
- 后台硬性安全检查仍然存在；
- 编辑器换图操作简单且支持共享图片库；
- 人工决定可以持久保存；
- 单槽重搜和缓存行为正确；
- 最终版面复查真实执行；
- 2000px 成品正确；
- 非图片业务功能未被破坏。
