## 一、这次要解决什么问题

新智能体不能每次把01—06全文全部交给模型，也不能让模型自由决定“要不要读某条规则”。这两种做法分别会造成速度慢、Token浪费、规则被淹没，或重要事实/安全规则被漏掉。

本任务要形成一份正式、可执行的调度规范，明确：

> 当前是什么任务 → 必须读取哪些规则 → 可以补充哪些规则 → 允许调用什么能力 → 输入和输出是什么 → 能否并行 → 失败后怎么处理 → 什么时候需要用户确认。

本次只把这套逻辑设计清楚并完成规则覆盖核对，不修改运行程序。

## 四、推荐的规则加载结构

正式规范必须采用以下四层结构，并说明每层由谁负责强制：

### 1. 全局硬规则

任务启动时固定版本，整个任务有效。主要包括：

- 原始资料和用户确认事实优先；
- AI不得修改日期、人数、路线、酒店、晚数、餐食、交通、费用和履约状态；
- 内部成本、利润、供应商底价、审核和来源信息不得进入客户结果；
- 不得自动改变产品安排或添加未采用的新体验；
- 不得使用AI生成图片进入正式客户成品；
- 调用次数、并发、超时、重试和费用不得突破管理员配置；
- 新智能体100%完成门禁、取消任务和项目隔离规则。

这些规则优先由确定性程序强制，不以模型“记住”为唯一保障。

### 2. 任务必需规则

由任务类型固定映射。例如酒店文案任务必须取得酒店事实规则和酒店表达规则；图片搜索必须取得图片位事实、来源、技术安全和搜索预算规则。智能体无权删除。

### 3. 条件与模块规则

只在本项目存在相应事实时加载，例如特色餐饮、自费体验、儿童长者、草原飞机、海上活动、签证时效信息。智能体可以提出增加，但只能从白名单选择，程序负责校验适用条件。

### 4. 最终检查规则

在真实结果形成后按事实、文案、图片和版式分别检查。最终检查不能依赖同一个模型对自己输出的主观自检，也不能通过整份重写掩盖局部问题。

## 五、必须定义的受控能力

正式规范至少定义下列能力。名称可以在文档中调整，但职责边界不能缺失：

| 建议能力ID | 用途 | 明确禁止 |
|---|---|---|
| `source_parser` | Excel与补充资料提取 | 不写客户文案，不猜事实 |
| `fact_validator` | 确定性事实、费用和履约检查 | 不自行选择冲突答案 |
| `human_confirmation` | 收集真正影响业务的用户决定 | 不询问可由程序自动处理的问题 |
| `trip_planner` | 规划整程内容主线、视觉主线和任务图 | 不改变产品事实和固定骨架 |
| `web_fact_search` | 核验官方酒店和时效事实 | 不添加新行程，不覆盖上级事实 |
| `copy_writer` | 按模块或连续DAY生成客户文案 | 不修改确定性字段 |
| `brand_reviewer` | 按规则发现品牌表达问题 | 不直接整份重写 |
| `target_patcher` | 只修改命中的字段、酒店或DAY | 不改无关模块，不无限重试 |
| `image_blueprint` | 规划图片位、视觉角色和搜索卡 | 不先搜图后填位，不生成图片 |
| `image_search` | 按slot搜索、下载和记录候选 | 不放宽地点、主体和安全硬条件 |
| `visual_auditor` | 图片三态、审美和图文一致性判断 | 系统错误不得推断为硬拒绝 |
| `layout_renderer` | 根据固定模板生成2000px页面 | 不改事实或文案含义 |
| `final_qa` | 检查事实、文案、图片和版式完成门禁 | 不用“看起来正常”代替证据 |
| `project_store` | 保存任务、版本、证据和结果 | 不混用旧流程项目数据 |
| `task_cancel` | 取消未完成调用并保存已取消状态 | 不把取消伪装成失败或完成 |

每项能力必须写清：允许输入、允许输出、可以修改的字段、禁止修改的字段、推理等级、调用预算、失败类型、重试上限、保存证据和用户可见状态。

## 六、必须覆盖的任务阶段

正式规范至少需要覆盖以下任务目录：

7. 条件模块显示/隐藏规划；

9. 全局、酒店/交通、连续DAY和收尾文案任务；
10. 文案事实比较和品牌审查；
11. 目标字段、酒店或DAY局部修复与复检；
12. 图片位必要性、稳定slot和视觉蓝图；
13. 图片候选搜索、下载、记录和安全检查；

## 七、并行与依赖要求

正式规范必须明确哪些任务可以并行，不能只写“尽量并行”。至少满足：

- 确定性事实确认结束前，不执行会把未确认事实写入客户结果的任务；
- 整程主线完成后，普通文案模块与不依赖最终文案的图片候选研究可以并行；
- 最终图片自动采用必须等待最终文案和图文一致性检查；
- 依赖联网事实的模块等待对应证据，不阻塞无关模块；
- 相邻DAY差异检查需要必要前后文，但不能把所有DAY重新串成一次整份生成；
- 品牌审查只审最终合并结果一次，命中问题后目标修复；
- 图片搜索与视觉审核采用连续队列，不等全部搜索完再统一开始审核；
- 任何单元失败只重试目标单元，不整份重跑；
- 100%门禁等待所有必需任务达到明确终态。

## 八、推理、预算和升级规则

正式规范必须把推理等级写成任务属性，而不是统一使用高推理：

- 高：整程内容/视觉主线、复杂DAY、跨日差异、最终品牌审查；
- 中或低：普通模块文案、结构清楚的连续DAY、图片搜索卡和明确目标润色；
- 最低或程序：字段提取、格式整理、固定结构、技术校验和机械重试；
- 只有低/中推理无法解决且任务属于允许升级类型时，最多升级一次高推理；
- 不得为了提速取消事实、安全、费用和履约硬检查；
- 标准7—10日行程完整目标仍为20分钟以内。
