# 智能体真实进度与可解释执行展示修订任务书

日期：2026-09-02  
状态：待后续修改，当前不实施  
适用项目：`D:\奢游\行程单报价单\奢游行程单美化-智能体试验区`

## 一、任务目标

让普通用户在完整生成过程中能够看懂智能体正在真实执行什么、已经完成什么、发现了什么问题、准备如何处理，以及发生等待或重试的原因。

本任务解决的不是“让百分比看起来一直上涨”，而是消除长时间停在同一个百分比所造成的卡死感和黑盒感。所有进度和状态必须来自真实任务、真实检查点和真实运行事件，不得按时间伪造进度。

## 二、当前问题

当前运行界面可能长时间停在同一个百分比，例如持续显示20%，虽然后台仍在生成、审核或重试，但用户无法判断系统是否还在正常工作。

现有状态还存在以下问题：

- `running`、`transport`、`days-all`、`closing`、`hotels`等内部英文名称直接展示，普通用户难以理解；
- 相同任务重试时可能重复出现相似记录，用户无法分辨是重复执行、正常重试还是程序异常；
- 只显示“正在生成”或“正在品牌审查”，不说明已完成数量、当前目标、发现的问题和下一步；
- 品牌审核、事实核验、文案生成、图片搜索、图片审核、渲染和最终检查缺少统一的可解释展示；
- 用户只能看到一个百分比，无法感受到智能体在进行真实判断。

## 三、产品原则

1. **展示真实工作，不展示伪进度**：百分比只能由真实任务完成状态、检查点和阶段权重计算，不能按照等待时间缓慢上涨。
2. **展示判断摘要，不展示模型内部推理**：向用户说明“发现了什么、依据是什么、准备怎么处理”，不得展示模型逐字思维过程、隐藏提示词、内部推理文本、API信息或技术密钥。
3. **所有能力采用同一展示标准**：本要求不只适用于品牌审核，也适用于规划、资料理解、事实核验、文案生成、目标重生成、图片规划、图片搜索、视觉审核、图片放置、渲染和最终检查。
4. **普通用户看到中文业务语言**：默认界面不得直接展示内部任务ID、英文模块名、字段路径或异常堆栈。管理员可以在独立的详情入口查看技术记录。
5. **等待也必须可理解**：长时间等待模型、搜索或渲染返回时，页面持续显示当前对象、请求状态和真实已等待时间，但不得制造不存在的新进展。
6. **失败和重试必须说清原因**：显示失败发生在哪个模块、为什么重试、当前第几次尝试、已完成结果是否保留，以及是否会从失败位置继续。

## 四、进度展示要求

### 4.1 总进度

总进度根据各阶段真实工作量和完成单元计算，并保持单调不倒退。至少展示：

- 当前总百分比；
- 当前阶段中文名称；
- 已完成单元数/总单元数；
- 已运行时间；
- 当前正在处理的具体对象。

并行任务不能用最后一条状态覆盖其他任务。总进度由所有任务的真实完成情况汇总，详情区同时显示正在并行执行的任务。

### 4.2 长任务内部进度

单次模型调用本身无法提供可靠百分比时，不伪造内部百分比。应展示真实可确认的节点：

- 已整理输入；
- 请求已发送；
- 正在等待返回，已等待X秒；
- 已收到结果；
- 正在检查结构与事实；
- 检查通过并已保存；
- 返回异常，正在进行第X次重试。

### 4.3 检查点与恢复

完成一个规划结果、文案模块、审核批次、图片模块或渲染结果后立即更新进度，并明确显示“结果已保存”。中断后续跑时说明哪些结果被复用、从哪个失败单元继续，不能让用户误以为整份重新开始。

## 五、统一的可解释执行信息

每条用户可见运行信息至少包含以下内容中的适用项：

- 正在进行的业务动作；
- 当前处理的模块、DAY、酒店或图片位；
- 已完成数量和剩余数量；
- 本阶段发现的问题数量；
- 问题属于硬问题还是优化建议；
- 系统采用的处理动作；
- 是否保留用户确认内容；
- 当前等待或重试原因；
- 下一步将进入什么阶段。

不得为了表现智能而输出空泛句子，例如“正在深度思考”“正在努力优化”。每条状态都要对应真实事件或真实任务变化。

## 六、各执行路径的展示示例

### 6.1 资料理解与规划

```text
正在理解原始资料
已识别13天行程、6家酒店、4种交通方式
正在判断哪些内容直接保留、需要优化或需要核验
```

### 6.2 文案生成

```text
正在生成每日行程
已完成 DAY 1—8，正在处理 DAY 9—12
本批结果返回后将检查事实和字段结构
```

### 6.3 品牌审核与目标重生成

```text
正在进行品牌审核
已检查8/13个内容模块
发现1项必须修改、3项优化建议
DAY 1、DAY 10已按用户意见直接保留

正在处理四季酒店文案
保留“泳池看大象”的核心卖点，补充为什么这一晚安排入住这里
```

品牌审核只展示经过整理的问题、依据和处理决定，不展示模型内部逐字推理。

### 6.4 事实核验

```text
正在核验2条具有时效性的外部信息
原始资料中的普通行程事实已经直接采用
已完成1/2条，正在等待官方来源返回
```

### 6.5 图片流程

```text
正在搜索酒店和每日行程图片
酒店图片已完成4/6，每日行程图片已完成7/13
正在审核DAY 8主图与当天体验是否一致
```

### 6.6 重试、超时与中断

```text
每日行程结果格式异常，正在进行第1次技术重试
DAY 1—8结果已经保存，不会重复生成
```

## 七、中文名称映射

用户界面至少完成以下中文转换，并为其他内部任务建立统一映射：

| 内部名称 | 用户显示 |
|---|---|
| `running` | 处理中 |
| `transport` | 全程交通 |
| `days-all` | 每日行程 |
| `closing` | 费用与注意事项 |
| `hotels` | 臻选下榻 |
| `dining` | 特色餐饮 |
| `brand_review` | 品牌审核 |
| `target_regeneration` | 局部重新生成 |
| `web_verification` | 事实核验 |
| `image_search` | 图片搜索 |
| `visual_review` | 图片审核 |
| `rendering` | 成品生成 |
| `final_qa` | 最终检查 |
| `retry` | 正在重试 |

| `failed` | 处理失败 |
| `cancelled` | 已取消 |

不得直接把未知英文内部名称显示给用户。没有中文映射的新任务在开发阶段应被测试发现。

## 八、普通用户与管理员视图

### 普通用户默认看到

- 中文阶段和模块名称；
- 真实完成数量；
- 判断摘要和处理动作；
- 等待、重试和中断的易懂原因；
- 下一步。

### 管理员按需展开查看

- 内部任务ID和目标字段；
- 调用开始与结束时间；
- 模型、搜索和审核请求状态；
- 技术错误分类与原始日志入口；
- Token、费用和重试记录。

管理员视图也不得展示模型隐藏推理或泄露API Key、完整提示词和其他敏感配置。

## 九、实施要求

- 优先复用现有运行事件账本、任务状态、检查点和调用统计，不另建一套重复的进度系统；
- 建立统一的进度汇总器，将阶段、任务、批次和检查点转换为总进度与用户可见事件；
- 建立统一中文名称映射，不在不同页面分别硬编码；
- 同一任务的重试更新原任务状态并增加尝试次数，不重复显示成多个无法区分的“正在生成”；
- 审核和修复事件必须关联同一目标，让用户能够看出“发现问题 → 处理问题 → 复检结果”的关系；
- 高频底层日志不得全部推到用户界面，应合并成可读摘要，完整技术日志保留在内部证据中；
- 本任务不改变100%完成门禁、不减少事实/品牌/图片/版面检查，也不修改模型、API Key、接口地址或计费配置。

## 十、验收标准

1. 模拟任一阶段持续运行3分钟以上时，总百分比即使暂时不增加，页面也能持续显示当前具体对象、真实等待时间和最近完成节点，用户能够判断系统未卡死。
2. 完成任一真实任务单元后，总进度和完成数量立即更新，不长期固定在20%等阶段占位值。
3. 并行执行酒店、交通和DAY文案时，分别显示各自状态，总进度按真实完成单元汇总。
4. 品牌审核能够显示已审核数量、硬问题与优化建议数量、当前问题摘要、处理动作和复检结果。
5. 事实核验、图片搜索、视觉审核、渲染和最终检查也使用同样的可解释展示，不只改品牌审核。
6. 所有普通用户可见模块、阶段、状态和错误信息使用中文，不出现`transport`、`days-all`、`closing`等裸英文内部名称。
7. 模型空结果、非法JSON、网络失败、单批超时和目标重试均显示易懂原因、尝试次数及已保留成果。
8. 中断恢复后明确显示复用了哪些已完成结果，只重新执行失败和未开始单元。
9. 用户取消后状态立即变为“已取消”，不继续产生伪进度或新的执行事件。
10. 用户界面不展示模型逐字内部推理、隐藏提示词、API信息、内部路径、异常堆栈或敏感配置。
11. 使用至少1份真实项目完成全链路录屏或连续截图证据，证明用户可以根据界面判断系统正在真实运转和进行可解释的业务判断。

## 十一、执行顺序建议

本任务在当前轻量规划、模块生成、检查点恢复和真实调用记账稳定后实施，避免先制作一套好看的假进度，再返工对接真实任务状态。

实施时建议按以下顺序：

1. 核对现有任务状态、检查点和运行事件是否足够支撑真实进度；
2. 统一阶段、模块、状态和错误的中文映射；
3. 建立真实进度汇总和长任务等待状态；
4. 建立判断摘要、问题处理和复检结果展示；
5. 接入品牌审核以外的全部执行路径；
6. 完成慢请求、并发、重试、中断恢复和取消测试；
7. 使用真实项目验证并保存证据。

完成后只能标记“开发完成，待独立复核”，不得仅凭页面演示宣布通过。
