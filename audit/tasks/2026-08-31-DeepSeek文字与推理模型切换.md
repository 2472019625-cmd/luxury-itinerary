## 第一部分：用户可读任务说明

### 1. 为什么要做

当前程序把客户文案、文字复核、图片规划、图片审核和最终长图视觉检查共用在一套模型配置里。直接把原模型名称改成 DeepSeek，会让图片请求也被发送给文字模型，可能导致图片审核和最终长图检查失败。

本次目标不是“全项目只改一个模型名称”，而是把文字规划任务和真实图片处理任务拆开：文字、文字推理及图片蓝图规划使用 DeepSeek；已经稳定运行的联网搜图、候选视觉审核、图片采用和最终长图视觉检查保持原样。

### 2. 本次确定采用的方案

- 客户文案首稿：切换为 `deepseek-v4-flash`。
- 品牌文案复核、文字规则推理：切换为 `deepseek-v4-flash`，使用更高推理强度。
- 图片蓝图规划：切换为 `deepseek-v4-flash`，使用较高推理强度；它只根据行程规划图片位和搜索主体，不负责观看候选图片。
- 联网图片搜索：保持当前 Gemini 搜索配置，不切换。
- 图片候选视觉审核：保持当前模型和调用方式，不切换。
- 最终 2000px 长图视觉检查：保持当前模型和调用方式，不切换。

这里的“真实图片链路不变”是指联网搜图、候选下载、视觉审核、图片采用和最终长图视觉检查不变；图片蓝图属于前置文字规划，本次切换到 DeepSeek。

### 3. 用户最终会看到的变化

- 客户文案和品牌文案复核由 DeepSeek 完成。
- 日期、人数、酒店、费用、路线和完成状态等程序硬规则不变。
- 文案仍然必须遵守 `rules/03-品牌文案与模块内容.md`。
- 图片搜索、图片审核、缺图处理和进入编辑器条件不变。
- 服务健康信息能够分别显示“文字模型”和“图片模型”，但不能显示任何 Key。
- DeepSeek 失败时显示清楚的文字模型错误，不再错误提示为“智谱内容生成失败”。

### 4. 本次不会改变什么

- 不改变 01—06 正式规则。
- 不改变图片搜索接口、搜索模型、搜索预算和并发。
- 不改变图片审核标准、三态、自动采用、缺图完成和用户锁定规则。
- 不改变最终 2000px 长图视觉检查。
- 不改变“全部生成和最终检查完成后才能进入编辑器”。
- 不改变客户数据、模板视觉、模型计费规则和旧项目冻结边界。
- 不使用或保存曾经发送到聊天窗口的 API Key。

### 5. 安全要求

已经出现在聊天窗口中的 Key 视为已暴露。用户随后明确要求直接完成切换，因此它只被写入本机 `.env.local`，没有写入代码、任务书、日志、截图、测试数据或交接文档；仍建议尽快在 DeepSeek 控制台轮换。

新 Key 只能由用户直接填写到本机：

`app/.env.local`

不得再次发送到聊天窗口。任何工具输出都不得打印 Key 或完整请求头。

### 6. 什么情况算失败

- 只修改模型名称，没有拆开文字和图片模型配置。
- 图片请求被发送到 DeepSeek 文字模型。
- 联网搜图、图片审核、图片采用或最终长图检查发生非预期变化。
- DeepSeek 返回的文字修改了日期、人数、酒店、路线、费用或其他确定事实。
- DeepSeek 返回格式不合格时，错误结果仍进入客户成品。
- DeepSeek 失败后程序静默切回其他文字模型，导致用户不知道实际使用了哪个模型或产生额外费用。
- Key 出现在代码、日志、健康接口、任务文件、截图或测试输出中。
- 只证明接口能调用，没有验证真实客户文案和完整流程。

### 7. 什么结果才算完成

- 文字首稿和品牌复核明确使用 `deepseek-v4-flash`。
- 图片链路仍使用切换前的模型和接口。
- 两类模型拥有独立配置，互不串线。
- DeepSeek 请求参数符合官方接口，不原样发送其他平台专用参数。
- DeepSeek 输出继续经过事实合并保护和文案质量检查。
- 自动测试证明文字和图片路由正确。
- 使用全新真实项目完成一次文字生成、图片流程、编辑器和 2000px 导出。
- 独立审查窗口确认文案规则、事实安全、图片链路和费用边界没有退化。

### 8. 仍需人工完成的事项

- 用户在 DeepSeek 控制台撤销已经暴露的旧 Key。
- 用户创建新 Key，并只在本机配置文件中填写。
- 独立审查窗口判断 DeepSeek 文案是否达到奢游品牌表达质量。

## 第二部分：技术执行附录

### 9. 修改目标

将当前单一 `BIGMODEL_*` 调用拆分为文字规划模型和真实图片处理模型。DeepSeek 接管客户文案首稿、品牌复核/文字推理及图片蓝图规划；现有图片搜索、视觉审核、图片采用和最终版面视觉复查不得迁移。

### 10. 配置设计

新增文字模型配置，建议采用清楚的供应商无关命名：

```text
TEXT_MODEL_API_KEY
TEXT_MODEL_BASE_URL=https://api.deepseek.com
TEXT_MODEL_NAME=deepseek-v4-flash
```

现有 `BIGMODEL_*` 暂时继续只为图片链路服务，避免本批同时迁移稳定图片配置。代码内部必须把它命名为图片/视觉提供方，不能继续误导为全部任务的统一模型。

保留：

```text
IMAGE_SEARCH_API_KEY
IMAGE_SEARCH_BASE_URL
IMAGE_SEARCH_MODEL
```

要求：

- 更新 `.env.example`，只写变量名和公开示例，不写真实 Key。
- `.env.local` 的真实新 Key 由用户本机填写。
- 不读取或转移聊天中暴露的 Key。
- 缺少文字 Key 时安全失败并提示“尚未配置 DeepSeek 文字模型”，不得调用图片模型代替。
- 不设置默认静默回退。未来如需回退策略，另行产品决策。

### 12. 调用层设计

建立轻量的文字模型调用模块，不开发复杂通用模型平台。该模块统一负责：

- DeepSeek Chat Completions 请求；
- `system` 和 `user` 消息；
- JSON Output；
- `thinking` 与 `reasoning_effort`；
- 超时；
- HTTP 错误和可读错误信息；
- 返回内容解析；
- 使用量和实际模型名称记录；
- 日志脱敏。

DeepSeek 官方基础地址使用 `https://api.deepseek.com`，当前程序再追加 `/chat/completions`。不得追加错误的双重 `/v1`。

请求不得照搬现有提供方专用字段，例如 `do_sample`、`clear_thinking`。使用官方支持字段：

```json
{
  "model": "deepseek-v4-flash",
  "messages": [],
  "stream": false,
  "thinking": { "type": "enabled" },
  "reasoning_effort": "low或high",
  "response_format": { "type": "json_object" }
}
```

本工具是单次结构化调用，不带工具调用和多轮推理历史；不得记录或向客户暴露 `reasoning_content`。

官方参考：

- `https://api-docs.deepseek.com/`
- `https://api-docs.deepseek.com/guides/thinking_mode/`
- `https://api-docs.deepseek.com/api/create-chat-completion/`

### 14. 数据和文案规则

- DeepSeek 只能修改客户表达字段。
- 日期、人数、路线、酒店、晚数、餐食、交通、费用、体验状态和履约边界继续由确定性程序保护。
- DeepSeek首稿继续经过 `mergeRefinement`。
- 品牌复核继续经过 `content-quality` 和最终数据QA。
- JSON缺字段、索引错误、重复DAY、额外DAY或事实冲突时拒绝模型修改并安全回退。
- 不降低 COPY-001—COPY-017 的任何要求。

### 15. 异常处理

- 未配置新 Key：明确提示，不启动文字生成。
- 401/403：提示文字模型认证失败，不打印Key。
- 429：提示限流，可有限退避重试，不切换图片模型。
- 5xx/超时：有限重试，失败后保留任务错误和可重试入口。
- 非JSON或结构错误：有限重试；仍失败则使用确定性安全回退，不进入错误文案。
- 文案质量未通过：只局部重写问题板块；达到重试上限后保留安全结果和风险记录。
- 图片模型或搜索异常：继续走原有图片异常路径，本批不改变。
