## 一、用户可读任务说明

### 1. 要解决的问题

当前程序虽然新增了客户文案提示词和基础检查，但真实生成结果仍会出现卖点只有标签、每日行程像供应商流水账、酒店与交通只说明安排而没有说明客户价值等问题。程序仍可能把这些文案判断为通过。

### 2. 本次目标

- 让模型在生成时收到完整、明确、分模块的奢游品牌表达要求。
- 让程序检查标题、卖点、酒店、餐饮、交通、每日行程、费用和注意事项是否达到对应要求。
- 首轮文案完成后必须进行品牌编辑复核；发现问题时只重写文案字段，不改变行程事实。
- 重写后仍存在品牌或安全问题时，不得把结果标记为合格。
- 保存规则覆盖、首轮问题、重写结果和最终检查记录，供独立审查复核。

### 3. 不在本批范围

- 不修改图片搜索、图片审核和图片采用规则。
- 不修改模型名称、API Key、接口地址、计费配置或 `.env`。
- 不改变日期、人数、路线、酒店、晚数、餐食、交通、价格、费用边界和体验状态。
- 不修改冻结历史项目。

### 4. 用户验收标准

- 产品亮点不能再只出现“顶奢连住、一价全包”之类裸标签，必须说明客户得到的具体价值。
- 酒店文案能说明位置价值、体验场景和对路线节奏的帮助，不能照搬设施清单。
- 每日正文能让客户看见时间推进、自己的动作或现场画面，并理解为什么值得。
- 相邻日期不能只是更换景点名的同义复写。
- 自费、可选、需预约和待确认体验的吸引力表达与费用边界同时保留。
- 注意事项温和、具体、可执行，不在每日正文堆警告。
- 最终质量记录必须逐项显示COPY-001—COPY-017的检查结果，不能只写“测试通过”。

## 二、技术执行附录

### 1. 运行链

1. `compactForModel`提供确定性事实和客户偏好。
2. 完整品牌生成提示词生成第一版结构化客户文案。
3. `mergeRefinement`只合并允许改写的客户表达字段，确定性事实仍取源数据。
4. `reviewCustomerContent`执行确定性结构、安全、品牌反模式及模块完整性检查。
5. 品牌编辑复核模型接收源事实、第一版文案、检查问题和COPY规则清单，输出针对性修订稿。
6. 再次按源事实合并并执行最终质量门禁；仍有问题则阻止作为合格文案继续生成。

### 2. 必须覆盖的规则

- COPY-001—002：品牌人格、表达顺序和固定模块职责。
- COPY-003—006：标题、副标题、产品亮点、行程总览。
- COPY-007—009：酒店、特色餐饮、交通。
- COPY-010—013：每日叙事、体验状态、今日贴士、注意事项。
- COPY-014—017：费用表达、承诺边界、定制师真实性、内部信息隔离。

### 3. 异常处理

- 模型返回非法JSON、DAY数量或编号错误：拒绝该轮结果，不以部分结果覆盖源数据。
- 首轮品牌问题：进入一次品牌编辑复核，不修改确定性事实。
- 复核后仍有质量问题：生成失败并返回具体问题，不以“安全清理”冒充品牌重写完成。
- 内部信息、费用状态冲突或无依据保证：始终为阻断问题。

### 4. 自动测试

- 不合格真实样式必须被检出：裸卖点、供应商流水账、百科腔、廉价促销、无场景每日文案、跨日近似重复、酒店设施堆叠、内部词和无依据承诺。
- 合格样式必须通过：卖点含客户价值、酒店含位置与路线价值、每日有推进与画面、注意事项温和可执行。
- 验证确定性事实和体验状态不会被文案复核改变。
- 从 `app/` 运行 `npm run test:rules`、`npm run test:images`、`npm run build`。
