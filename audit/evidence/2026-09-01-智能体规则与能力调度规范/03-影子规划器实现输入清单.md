# 影子规划器实现输入清单

日期：2026-09-02
用途：下一批代码任务的产品输入；本批不创建配置、schema或规划器代码

## 一、开始编码前必须已有的版本化输入

1. `ruleProfileVersion`：92 条规则 ID、四层分类、任务必需映射、条件白名单、最终检查映射和新/旧流程适用范围。
2. `capabilityConfigVersion`：15 项能力的输入/输出 schema、可改/禁改路径、推理策略、预算键、失败类型、重试和状态映射。
3. `promptVersion`：只为 `trip_planner` 的影子计划提示词；第一阶段不得包含真实文案、联网、搜图或审核提示词调用。
4. 产品决定：DEC-001—DEC-006 已全部确认，不再输出 `decisionRequired`；实现必须逐项引用决定版本。
5. 流程隔离值：`flowKind=agent_v1`、专用入口、默认4174且允许记录受控回退端口、独立浏览器数据、独立测试项目目录和项目命名空间；不得占用或误连4173。
6. 输入范围：主行程仅单份受支持Excel；补充白名单为可提取文本PDF、DOCX、TXT、Markdown和用户授权图片。影子阶段只记录类型、来源和用途，不做解析、OCR或事实覆盖。

## 二、建议创建的配置与 schema（下一批）

| 文件/对象 | 最低内容 | 校验重点 |
|---|---|---|
| `app/config/agent-task-routing.json` | T01—T20、任务类型、L1/L2/L3/L4、能力、推理、预算键、失败策略 | 92 ID均存在；L1/L2不可删除；无未授权能力 |
| `agent-plan.schema.json` | 正式规范第八章全部字段、项目版本和计划摘要；六项产品决定直接成为固定校验值 | required字段、枚举、无额外敏感字段 |
| `agent-capability.schema.json` | 输入/输出、mutable/forbidden paths、预算、证据、状态 | 可改/禁改不重叠；预算不可由模型填写真实值 |
| `agent-rule-profile.schema.json` | 规则版本、适用流程、层级、任务映射、条件 | 单ID单主责、条件可确定性验证 |
| `agent-plan-validator` | schema、版本、覆盖、授权、目标路径、依赖、并行、预算和状态校验 | 任一失败不调用真实能力 |
| `shadow-planner` | 从已确认事实摘要生成结构化任务计划 | 仅输出计划；不联网、不生成客户文案/图片/成品 |
| `shadow-plan-view` | 人可读阶段、依赖、失败和确认摘要 | 不显示模型推理、内部提示词、密钥和费用配置 |

文件名是实现建议，不在本批创建；正式任务书可调整命名，但不得减少字段或安全边界。

## 三、确定性校验顺序

```text
解析 JSON
→ schema 与 required 字段
→ 项目 flowKind 和三版本一致
→ taskType/targetPath 白名单
→ capabilityId 授权与可改路径
→ L1/L2 完整、L3 条件成立、L4存在
→ rule ID 都属于92条且无重复
→ dependsOn 无环、并行不越门禁
→ timeout/retry/cost 只引用管理员预算键
→ failure/userConfirmation/status 映射完整
→ 所有能力调用标记 plan_only
→ 通过后只保存和展示影子计划
```

失败只能返回具体错误，例如 `copy.day.004 缺 COPY-010`、`image_search 不允许修改 customer.days`；不能只写“规划失败”。校验器可以要求规划器针对错误位置修正一次，仍失败则保存 `planning_failed`。

## 四、最小影子测试矩阵

| 场景 | 应证明 |
|---|---|
| 资料完整的7—10日项目 | T01—T20必要节点齐全；无无意义确认；普通任务可并行 |
| 日期/晚数/费用冲突 | T04→T05，确认前不生成客户结果 |
| 酒店官方事实待核验 | 只阻塞相关酒店/DAY；无关模块继续 |
| 连续相似DAY | 连续小单元+前后摘要；差异审查不整份重写 |
| 自费/待确认体验 | 文案、图片蓝图、费用和状态规则同时加载 |
| 图片搜索预算耗尽 | 非必需位移除任务；必需位等待确认；无空白完成路径 |
| 最低图片位必要性 | 程序输入固定封面1张、每个展示酒店1张主图、每个展示DAY 1张主图；AI试图降级时校验失败 |
| 审核服务超时/429/5xx | 候选转manual；不记硬拒绝、不自动采用 |
| 文案普通建议未修复 | 只生成 `user_accepted_suggestion`；保留问题/规则ID/决定/时间，不得标passed |
| 事实/安全/内部泄漏 | 不允许用户接受绕过；回目标确认或中断 |
| 用户取消 | 当前项目已取消、调用尽力终止、项目保留、不可继续/导出 |
| 输入指纹未变的局部恢复 | 已完成单元复用，失败目标单独重试 |
| 完整重新生成 | 新建独立项目，不覆盖原项目 |
| 商业授权待确认/拒绝 | 待确认时100%和编辑器不变但正式导出为零；拒绝时只替换/补授权/停止导出，不重生重审 |
| 补充资料越界 | OCR、旧`.doc`、聊天记录或补充资料覆盖Excel时校验失败；提取失败要求可读文本 |
| 删除/回收站任务 | 第一批计划校验失败，不产生删除能力或界面承诺 |
| 恶意计划：删必需规则 | 校验失败，不执行 |
| 恶意计划：未授权能力/越权路径 | 校验失败，不执行 |
| 恶意计划：引用98%或占用/误连4173 | 适用范围校验失败 |

## 五、证据输出

每次影子运行至少保存：原始输入引用和指纹、项目/规则/能力/提示词版本、模型原始结构化返回（内部）、校验错误、最终计划、规则覆盖报告、能力权限报告、依赖图、用户可见摘要、耗时与调用统计。不得保存或展示模型推理正文；客户视图不得出现规则全文、内部路径、审核分数、来源账本或费用配置。

## 六、完成定义

下一批影子规划器只有在以下条件同时满足时才可交独立复核：

- 92 条规则配置与本覆盖表一一对应；
- 20 个阶段至少都有可触发/不适用的确定规则；
- 15 项能力只能被授权任务引用；
- 字段、依赖、并行、预算、重试和用户确认均通过确定性校验；
- 所有场景只输出计划，网络、文案、图片、放置、渲染和导出调用次数为零；
- 旧固定流程入口、4173、项目数据和冻结行为未改变；
- 新智能体使用4174或有证据的受控回退端口；
- 六项产品决定均有确定性计划校验，且没有回收站/删除能力；
- 提交自动测试、全新影子项目证据、已知问题和待独立复核项。
