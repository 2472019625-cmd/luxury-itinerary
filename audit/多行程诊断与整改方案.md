## 已定位的项目问题

### DIAG-01 搜索额度拒绝被误报为“无结果”

肯尼亚10日顶奢的五个图片位、十次 Web 搜索调用被上游以预扣额度不足拒绝：封面、DAY8/9/10 主图及 DAY2 辅图。前四位必需，后一位可选。逐位证据均为两条拒绝警告、两次已执行查询、零返回页面；这里没有可以用来评价关键词质量的成功搜索结果。

项目最终却标记 `no_search_results`。`app/server/simple-image-skill.mjs` 约 2268—2277 行用 `allSettled` 保存上游拒绝；约 2438—2444 行在 Web Provider 与 Commons 都拒绝时才认定全部搜索失败。Commons 成功但结果为空时，主搜索的明确异常被降格为空结果。

应分别归因：上游搜索服务因额度条件拒绝提供服务；项目对混合来源结果聚合错误，误导了后续诊断。这不是随机网络抖动，也不能用换关键词或增加重试解决。本轮没有调整额度、计费或接口配置。

整改方向：区分来源级 `success_empty`、`failed` 与 `unavailable`，保留可采取行动的错误类别。额度拒绝等确定性异常应明确呈现；是否暂停同源后续请求需在既有业务预算内规定，不应继续以换词掩盖不可用。

### DIAG-02 网页召回偏离画面，Query 与 Scope 的传递需按规则核对

坦桑尼亚8日野趣 DAY7 的规划画面是“营地夜空下璀璨银河”，但实际 Web 查询只有 `starry night sky and Milky Way`，备选为“星空银河”。搜索返回中出现天文软件渲染、智利天文台及地点无法核实的银河照片。

`app/server/image-web-execution.mjs` 的英文 Core 合成优先使用 `subjectEn`，地理补充依赖英文字段或实体注册表转换。本次只有中文目的地，缺少对应英文目的地映射，营地语境也未进入实际查询。查询过宽是召回偏差的可证实贡献因素；不能因此断言搜索供应商发生故障，也不能保证补入地名后一定有合格图。

整改方向：以当前图片规则中的 Core、Scope、Prefer 分工核对字段传递。Query 只保留必须入镜的核心主体和必要动作；地点若只是检索范围，由 Scope 承担，氛围由 Prefer 承担。只有具备来源且属于不可替代视觉身份的场景或地点才进入 Core。必要 Core 的英文映射缺失时提供忠实回退，不能静默丢失；不能把国家、营地、氛围一律拼进搜索词，也不能把普通体验强行升级为精确实体图片位。本例已证明召回偏差，但补入哪些词仍须依据该图片位的正式 Core，不能仅凭结果倒推规则。

### DIAG-03 失败原因被后一次查询覆盖

坦桑尼亚8日野趣酒店3，知识库已有审核未完成的预览，Web 已审核的一张图是 `wrong_subject`；后续查询的尺寸失败却把最终 `technicalStatus` 覆盖为 `all_candidates_too_small`。因此最终提示不能证明知识库原件低清。

主要实现位置：`app/server/simple-image-skill.mjs` 的逐 Query 结果合并、继续查询判定，以及仅依据当次下载失败生成技术状态的分支。相关代码在本候选约 2205、2225、2434—2444 行。

整改方向：保留阶段级状态，聚合时依据完整候选池决定主因和次因。明确区分未检索、无召回、获取失败、原件尺寸不足、主体错误和审核未完成，不能用最后一次失败覆盖已有证据。

### DIAG-04 合法标题同义表达被正则误判

坦桑尼亚8日顶奢 DAY6 原 Excel `Sheet1!A11:C11` 支持马拉河、大迁徙和“天国之渡”主题。生成标题“马拉河上的天国之渡”被标为 `unsupported_copy_commitment`，直接原因是概念匹配只识别“迁徙／渡河／river crossing／migration”，不识别该同义表达。

相关实现：`app/server/simple-copy-skill.mjs` 的概念正则、`validateVisualCardSubjectRetention()` 和 `validateCopyCommitments()`（约 209、222—229、248 行）；`app/server/simple-plan-adapter.mjs` 将 Planner 主体传为 `titleCoreSubject`（约 1003—1004 行）。

整改方向：将“新增事实承诺”和“标题压缩、同义表达”分开校验，以同一事实对象及受控语义映射判断，不要求短标题逐字复述完整画面。Planner 加入的角马、鳄鱼等细节不能反向成为 Excel 已确认事实。

肯尼亚8日野趣也出现同类问题：可选 DAY1 辅图标题“乞力马扎罗山脚下的落日酒会”因没有保留英文 Sundowner 词形被报 `unsupported_copy_commitment`；原目标同时已有“Sundowner落日酒会”这一中英文对应。该项非必需，需与该份三个必需缺图分开统计。

### DIAG-05 酒店目标生成与来源校验衔接造成零搜索

肯尼亚8日顶奢的三个必需酒店位在搜索前停止：两个为 `hotel_specific_visual_source_unconfirmed`，一个为 `ambiguous_visual_subject`。三个位置均无知识库/Web 请求及候选，不能归为知识库未命中。

原 Excel 的酒店名称、路线及晚数与导入一致，但没有提供酒店公共空间面向山景、帐篷与草原等摄影画面描述。Planner 将目标具体化后被来源校验停下，属于目标生成与校验的衔接问题；不能单凭图片引用字段为空断言酒店身份无来源。另一个画面明确包含“外观或大堂公共区域”两个选项。相关入口是 `app/server/agent-trip-planner.mjs` 的酒店画面来源与代表空间归一校验；`app/server/simple-image-skill.mjs` 在 unresolved 分支直接跳过搜索。肯尼亚10日顶奢还出现一个必需酒店位规划未决、零搜索。

整改方向：在同一次 Planner 输出中确定一个可搜索画面，统一酒店代表空间与特定设施承诺的边界。只做有确定依据的局部归一，无法确定的目标继续保留人工处理；不新增整份规划重跑，也不通过放宽酒店身份门槛补数。

肯尼亚8日野趣 DAY6 也在搜索前被拦截，原因是 `scope_only_location_in_query` 与 `ambiguous_visual_subject`。这表明衔接问题不限于酒店位；不能把未发起的请求算成知识库或搜索服务失败。

### DIAG-06 视觉审核缺少软评分使候选无法采用

坦桑尼亚8日野趣 DAY7 已有两张自然银河候选，归一化硬判断记录为 `eligible=true`、身份不要求唯一实体；但审核契约仍缺 `score`，一次技术补全后未满足完整契约，最终为 `visual_judgment_inconclusive`。错误类别是审核契约未完成，不是搜索零结果。

当前证据没有保存原始结构化审核响应，不能区分上游漏字段与项目解析映射问题。`app/server/image-audit.mjs` 明确要求及补全 score，`app/server/image-audit-contract.mjs` 将其列为必填；当前实现因此让软评分缺失阻止自动采用。

整改方向：先保留脱敏的原始结构化返回及归一化差异，排查字段映射；再明确事实/身份/真实性硬判断与排序字段的完成契约。不得伪造分数或默认审核通过。

肯尼亚10日顶奢 DAY2 与 DAY6 的同名最终状态不属于此缺字段问题：两位已审核候选的契约完整，仍无法证明指定地点身份。DAY2 有象群、雪山图，但身份依据不足；DAY6 的候选不能证明属于 Solio，另有水印和错误酒店标识被拒。现有证据支持保留人工处理，不能把身份硬门禁视为代码漏洞或为提高采用率放宽。

### DIAG-07 采用前尺寸合格不等于最终版面适配

坦桑尼亚8日顶奢有一张交通图原件 774×945，在最终版面显示为 1125×640，缩放 1.4529 倍，超过 1.35 倍上限。QA 的六条卡图测量记录中只有这一条超限，不能把测量记录数量当作缺陷数量。实际原图可辨认游猎车，问题发生在最终版面尺寸衔接。

整改方向：使用最终卡框和裁切方式复核，区分草稿警告与正式导出阻断；不能用增大允许放大倍数解决。

## 知识库与外网边界

本次目录接口真实返回 HTTP 200、509 个目录节点，首次约 52ms。目录可达不能证明图片查询、索引和原件均正常。Naboisho 当前使用马赛马拉父级范围，属于目录粒度较粗；丽思目录拼写不同但本次已定位，都不能仅凭名称定为失败原因。

原始记录共引用 165 次查询，其中第五份 DAY7 辅图与 Carnivore 餐饮图共用一个已完成 queryId，因此独立任务为 164 个。8 个 failed 又分为 5 个 terminal_failure 和 3 个 transport；10 个 timeout 为轮询期限耗尽。不能将它们统称为服务端崩溃。

首份五次异常都由同批 Web 接续找到图片，故它们真实影响等待和外网工作量，却不是该份最终四个必需缺图的直接原因。第三份三次异常中，一位 Web 接续成功，另两位随后在网页提取或下载解码阶段失败，属于多层问题叠加。

第四份七次知识库异常中，四位 Web 接续成功，两位有候选但视觉审核未确定，一位 Web 接续又遭遇搜索额度拒绝。该份最终七个必需缺图为：四个被误标为 `no_search_results` 的搜索额度拒绝、两个 `visual_judgment_inconclusive`、一个规划未决。知识库异常数不能直接当作最终缺图数。

其中前三条约 100 秒后出现的 terminal failure 经既有 output 接口只读回查，仍返回 `status=failed`。返回错误没有可用的机器可读细因；当前没有服务端日志证据，不能断言队列、算力、上游服务或超时阈值就是根因。约 30 秒传输失败、约 120 秒客户端轮询超时也应分别记录。

按用户确认的 SSH 目标与用户名连接，主机指纹匹配但身份认证未通过；没有进入远端执行命令，也没有修改远端服务。内网 API 证据可用，SSH 服务日志与索引完整性仍是验证缺口。

外网页面的拒绝访问、提取为空、解码失败与搜索服务本身失败是不同层次。已经看到部分来源页验证/拒绝和错误主体候选；第四份还确认搜索 Provider 因额度拒绝。现有证据不能证明更换搜索供应商可以解决所有问题。预览尺寸也不能证明未下载原件的尺寸。

五份实际 Web Provider 调用分别为 14、20、10、17、12 次，共 73 次，与程序 `metrics.searchCalls` 一致；第四份有 10 次上述额度拒绝，其余四份未记录 Provider 拒绝。其余 63 次已完成 Provider 调用均返回至少一个来源页，未观察到 Provider 正常完成且空结果。该口径取 `queryReports.returnedPages`，该字段仅统计 Provider 页面，不含 Commons。五份页面获取失败另有 17、27、14、6、7 条事件，不能将这些事件与搜索调用相加计算“搜索失败率”。

第五份的 12 次 Provider 调用恢复正常，故不能把第四份的预扣额度拒绝外推为永久余额耗尽。拒绝发生及消失的账户、路由或额度条件需要服务方记录解释，本轮没有这方面证据，也没有调整配置。

典型的多层结果还包括：第一份封面没有匹配目录，Web 仍拿到图片但缺身份依据；第三份酒店2在知识库失败后搜到官网页面，却在页面提取阶段没有得到图片；第三份 DAY8 在知识库传输失败后遇到网页、下载解码和主体审核问题。每条路径应保留完整阶段，不能只用最终一个标签给整条链路定责。

第五份的三个必需缺图分别为：酒店3目录需要澄清后转 Web，查询有页面但候选下载失败；DAY6 在 Planner 校验阶段停止；DAY7 知识库轮询传输失败后转 Web，虽有页面但视觉审核仍未确定。其交通2也是未采用图片位，但为可选位，不计入三个必需缺图。

## 验证覆盖与边界

测试代理直接读取五份原 Excel 的 DAY 单元格，对照最终供 Renderer 使用的 `city`、酒店与 `mealPlan`。分别覆盖 8、8、8、10、8 天：路线按空白及交通符号归一对照、住宿名称对照、早午晚餐类别结构对照均相符；酒店晚数合计分别为 7、7、7、9、7 晚。原表没有明确的固定出行日期和成人/儿童订单人数，最终保留未知；不能把报价人数当作订单人数。

## 后续整改验收要求

建议实施顺序和可判定的验收标准如下；本轮没有实施这些修复。

状态聚合修复首先提高诊断准确性，不承诺自动提高出图率。关键词修复、候选身份依据补充和上游服务恢复分别解决不同问题，不能相互替代。

### 新酒店事实链路的具体边界

当前新入口以页面标题和 URL 的酒店名称词元作初筛，并不等于完整酒店身份核验。现有事实行归一化会检查字段结构及来源 URL 是否来自本次结果，但不能证明该网页真的支持生成的每句话；snippet 分支也应像原有回退分支一样，在程序合并时落实原始资料优先级。

建议保留同一研究结果供酒店正文、卖点及事实行复用，在既有结果结构中关联 entity、事实类别、原始片段、来源 URL 与取得时间，写作只能从可定位的片段提取或忠实改写。程序负责实体关联、引用存在性、字段和来源优先级校验；这些结构检查不能冒充语义真实性验证，事实支持程度仍需在定向验收中检查。不增加一套串行模型审查，也不把所有结果重新走一次全网页抓取。

对于无来源、同名酒店无法消歧、供应商资料与网络冲突的内容，分别保留明确状态；可写内容继续写，不以猜测填满四类字段。不把酒店公共设施自动写成本订单已含服务，不把官方列出的房型当作本次已订房型。
